Lecture 34: Web Application Architectures (Model 1)

1. What is Web Application Architecture?

Technical Definition: Web Architecture refers to the layout and interaction of different components (like Servlets, JSPs, and JavaBeans) in a web application. Java introduced two primary architectures for building web applications: Model 1 and Model 2.

2. Model 1 Architecture

In Model 1, the JSP page is responsible for everything. It handles the user's incoming request, performs business logic (usually by calling JavaBeans), and generates the HTML response.

Roman Urdu Explanation: Model 1 mein JSP hi sab kuch karta hai. User ka form data JSP mein aata hai, JSP database se connect hota hai (JavaBeans ke zariye), aur phir wahi JSP output screen pe dikhata hai. Shuru mein yeh aasaan lagta hai, lekin jab project bada ho jaye, tou HTML aur Java code itna mix ho jata hai ke usay samajhna aur theek karna (maintain) azaab ban jata hai. Is mix code ko "Spaghetti code" kehte hain.

Drawbacks of Model 1:

  • No Separation of Roles: Web designers (HTML/CSS) and Programmers (Java) have to work on the same JSP file, causing conflicts.
  • Hard to Maintain: Code becomes complex and unreadable ("Spaghetti Code").
  • Reusability is Low: Business logic stuck in one JSP cannot be easily used by another.

Quick Revision - Lecture 34

  • Model 1: JSP handles both Processing (Logic) and Presentation (UI).
  • Key Components: Browser ➔ JSP ➔ JavaBeans ➔ Database.
  • Biggest Problem: Spaghetti code, mixing design with programming logic.

Lecture 35: Model 2 Architecture (MVC Pattern)

1. What is Model 2 (MVC)?

Technical Definition: Model 2 architecture solves the problems of Model 1 by adopting the MVC (Model-View-Controller) design pattern. It strictly separates business logic, presentation, and request handling into three distinct components.

  • Model (JavaBean): Holds the data and the business rules (e.g., Database connection, calculations).
  • View (JSP): Only responsible for displaying data to the user. (No Java logic).
  • Controller (Servlet): Acts as the manager. It receives the request, asks the Model to process it, and forwards the result to the View.
Roman Urdu Explanation: MVC mein kaam divide ho jata hai. Jab aap button click karte hain, tou request seedha JSP par nahi, balke Servlet (Controller) par jati hai. Servlet check karta hai aapne kya bheja hai, phir wo JavaBean (Model) se kehta hai ke data process karo (jaise login verify karna). Jab Bean result de deta hai, tou Servlet us result ko pakar kar JSP (View) ki taraf bhej deta hai taake user ko dikhaya ja sakay. Design aur Logic bilkul alag ho gaye!

2. How MVC works in Code (The Controller)

The core of Model 2 is how the Servlet (Controller) passes data to the JSP (View). We use the RequestDispatcher for this.

// 1. Inside a Servlet (Controller)
protected void doPost(HttpServletRequest request, HttpServletResponse response) {
    
    // a. Capture input
    String user = request.getParameter("username");
    
    // b. Talk to Model (JavaBean)
    UserBean myBean = new UserBean();
    myBean.setName(user);
    
    // c. Store the Bean inside the 'request' so JSP can find it
    request.setAttribute("userData", myBean);
    
    // d. Forward the request to the View (JSP)
    RequestDispatcher rd = request.getRequestDispatcher("welcome.jsp");
    rd.forward(request, response);
}

Explanation:

  • request.setAttribute("userData", myBean): This is crucial. The Servlet attaches the populated Bean to the request object under the name "userData".
  • RequestDispatcher: An interface used to send the request from the Servlet to another resource (like a JSP file) on the server.
  • rd.forward(): Transfers the control. The user's URL doesn't change, but the server internally loads the JSP.

3. How MVC works in Code (The View)

<!-- Inside welcome.jsp (View) -->
<html>
<body>
    <!-- 1. Use the bean stored by the Servlet in the 'request' scope -->
    <jsp:useBean id="userData" class="com.example.UserBean" scope="request" />
    
    <!-- 2. Display the data (No Java scriptlet needed!) -->
    <h1>Welcome, <jsp:getProperty name="userData" property="name" /></h1>
</body>
</html>
Important Rule (Scope): When passing beans from Servlet to JSP, the scope in request.setAttribute() MUST match the scope in <jsp:useBean scope="...">. In MVC, this is almost always scope="request".

Quick Revision - Lecture 35

  • Model 2 (MVC): Clear separation of concerns.
  • Controller: Servlet (Intercepts, manages flow).
  • Model: JavaBean (Data, Logic, DB).
  • View: JSP (HTML Presentation).
  • RequestDispatcher: The mechanism used by Servlets to forward requests to JSPs.

Lecture 36: Introduction to XML

1. What is XML?

Technical Definition: XML stands for eXtensible Markup Language. Unlike HTML (which is designed to display data), XML is designed to store and transport data. In XML, there are no predefined tags; you invent your own tags to describe the data.

Roman Urdu Explanation: HTML mein pehle se tay shuda tags hote hain (jaise <p> paragraph ke liye). Lekin agar aapko ek student ka data bhejna ho, tou HTML ka koi <student> tag nahi hai. XML aapko azadi deta hai ke aap apne data ke hisaab se khud tags banayein. Iska maqsad data ko khoobsurat dikhana nahi hai, balke data ko safe tareeqay se ek system se doosre system tak pohnchana hai.

2. Basic XML Syntax and Rules

<?xml version="1.0" encoding="UTF-8"?>
<!-- 1. Root Element (Mandatory) -->
<bookstore> 
    <!-- 2. Child Element -->
    <book category="programming"> 
        <title>Java Basics</title>
        <author>John Doe</author>
        <price>500</price>
    </book>
</bookstore>

Strict XML Rules:

  1. Single Root: Every XML document MUST have exactly one root element that encloses all other elements (e.g., <bookstore>).
  2. Case Sensitivity: <Author> and <author> are completely different.
  3. Closing Tags: Every tag must be closed. (<title>...</title>).
  4. Proper Nesting: Tags cannot overlap. (<b><i>Text</b></i> is illegal in XML).
  5. Quotes for Attributes: Attribute values MUST be in quotes. (category="programming").

3. Well-Formed vs Valid XML (Important Exam Topic)

  • Well-Formed XML: An XML document that follows all the strict syntax rules mentioned above.
  • Valid XML: An XML document that is "Well-Formed" AND also conforms to a predefined structure called a DTD (Document Type Definition) or an XML Schema.

Quick Revision - Lecture 36

  • HTML vs XML: HTML displays data, XML stores/transports data.
  • Tags: XML tags are custom and not predefined.
  • Root Element: Absolute requirement for XML.
  • Well-Formed: Follows syntax rules.
  • Valid: Follows syntax rules + DTD structural rules.

Lecture 37: XML Parsing using DOM

1. What is an XML Parser?

To read or modify XML files using Java, we need a software component called an XML Parser. Java provides two main types of parsers: DOM and SAX.

2. The DOM Parser (Document Object Model)

Technical Definition: DOM is a tree-based parser. It reads the entire XML file and creates a tree of Node objects in memory (RAM). Once the tree is built, developers can navigate up, down, or modify the nodes.

Roman Urdu Explanation: DOM parser poori XML file ko ek hi dafa RAM mein utha lata hai aur usko ek "Darakht" (Tree) ki shakal de deta hai. Iska faida yeh hai ke aap file mein kisi bhi waqt aage peeche ja sakte hain aur data change kar sakte hain. Lekin nuqsan yeh hai ke agar XML file bohot badi (jaise 2GB) ho, tou aapki RAM full ho jayegi aur program crash (Out of Memory) ho jayega.

3. DOM Code Example & Syntax

Important packages to import: javax.xml.parsers.* and org.w3c.dom.*.

import javax.xml.parsers.*;
import org.w3c.dom.*;
import java.io.File;

public class DOMExample {
    public static void main(String[] args) {
        try {
            // 1. Setup the Parser Factory & Builder
            DocumentBuilderFactory factory = DocumentBuilderFactory.newInstance();
            DocumentBuilder builder = factory.newDocumentBuilder();
            
            // 2. Parse the XML file into a Document (Tree) in memory
            Document doc = builder.parse(new File("students.xml"));
            
            // 3. Normalize the XML structure (fixes spacing issues)
            doc.getDocumentElement().normalize();
            
            // 4. Get a list of all <student> tags
            NodeList nList = doc.getElementsByTagName("student");
            
            // 5. Loop through the list
            for (int i = 0; i < nList.getLength(); i++) {
                Node node = nList.item(i);
                
                if (node.getNodeType() == Node.ELEMENT_NODE) {
                    Element element = (Element) node; // Cast Node to Element
                    
                    // 6. Extract data
                    String id = element.getAttribute("id");
                    String name = element.getElementsByTagName("name").item(0).getTextContent();
                    
                    System.out.println("ID: " + id + ", Name: " + name);
                }
            }
        } catch (Exception e) { e.printStackTrace(); }
    }
}

Explanation:

  • DocumentBuilderFactory / DocumentBuilder: Built-in Java classes that prepare the parsing engine.
  • builder.parse(): The critical step that actually reads the file and returns a Document object (The DOM Tree).
  • getElementsByTagName("student"): Returns a NodeList (array) of all elements matching the tag.
  • getTextContent(): Extracts the text between the opening and closing tags.
Common Mistakes / Rules:
  • Rule: In DOM, everything is a Node. Elements are Nodes, Attributes are Nodes, even the raw text between tags is a "Text Node". You must check getNodeType() == Node.ELEMENT_NODE before treating it like a standard tag.
  • Mistake: Using DOM for massive XML logs. Always use SAX for large files to avoid memory crashes.

Quick Revision - Lecture 37

  • DOM: Tree-based, Memory-heavy, Read & Write capable.
  • Best For: Small files where you need to modify the XML structure.
  • Core Classes: DocumentBuilder, Document, NodeList, Element.

Lecture 38: XML Parsing using SAX

1. What is the SAX Parser?

Technical Definition: SAX (Simple API for XML) is an event-based, sequential access parser. Instead of loading the whole document into memory, it reads the XML line-by-line from top to bottom. When it encounters a tag, it triggers an "Event" (like pressing a button) that calls a specific method.

Roman Urdu Explanation: SAX parser ek waqt mein sirf ek line parhta hai, us line ka data aapko deta hai, aur phir usko memory se nikal kar agli line par chala jata hai. Is waja se yeh bohot fast hai aur memory (RAM) bilkul gher-ta nahi. Lekin isme masla yeh hai ke aap file mein wapas peeche nahi ja sakte, aur na hi XML file ko edit kar sakte hain. Yeh sirf read-only hai.

2. How SAX Works (The Events)

To use SAX, you must create a class that extends DefaultHandler and override these specific event methods:

  • startDocument(): Triggered when parsing starts.
  • startElement(): Triggered when an opening tag is found (e.g., <name>).
  • characters(): Triggered when the text inside the tag is read.
  • endElement(): Triggered when a closing tag is found (e.g., </name>).

3. SAX Code Example

Important package: org.xml.sax.* and javax.xml.parsers.SAXParser.

import javax.xml.parsers.*;
import org.xml.sax.Attributes;
import org.xml.sax.helpers.DefaultHandler;
import java.io.File;

// 1. Custom Handler extending DefaultHandler
class MyHandler extends DefaultHandler {
    boolean bName = false; // Flag to track when we are inside 

    // 2. Triggered on 
    public void startElement(String uri, String localName, String qName, Attributes attributes) {
        if (qName.equalsIgnoreCase("name")) {
            bName = true; 
        }
    }

    // 3. Triggered on Text content
    public void characters(char ch[], int start, int length) {
        if (bName) {
            System.out.println("Name: " + new String(ch, start, length));
            bName = false; // Reset flag
        }
    }

    // 4. Triggered on 
    public void endElement(String uri, String localName, String qName) {
        // (Clean up or closing logic here if needed)
    }
}

public class SAXExample {
    public static void main(String[] args) {
        try {
            // 5. Setup SAX Parser
            SAXParserFactory factory = SAXParserFactory.newInstance();
            SAXParser saxParser = factory.newSAXParser();
            
            // 6. Start parsing! Pass the file and our custom Handler
            saxParser.parse(new File("students.xml"), new MyHandler());
            
        } catch (Exception e) { e.printStackTrace(); }
    }
}

Explanation:

  • extends DefaultHandler: We inherit this class so we only have to override the events we care about.
  • qName: The actual name of the XML tag being processed (e.g., "name").
  • bName = true: Because SAX is event-driven, when we see <name>, we set a boolean flag to true. When the characters() method fires right after, we check the flag to know *which* tag's text we are currently reading.

4. DOM vs SAX (Exam Comparison)

Feature DOM (Document Object Model) SAX (Simple API for XML)
Style Tree-based. Event-based.
Memory Usage High (Loads entire document). Low (Reads node by node).
Speed Slower (Must build tree first). Faster.
Navigation Can move forward and backward. Sequential (Top to bottom only).
Modification Can Edit/Add/Delete tags. Read-Only. Cannot modify.

Quick Revision - Lecture 38

  • SAX: Event-driven, low memory footprint, extremely fast.
  • Best For: Reading massive XML files where you only need to extract data, not edit it.
  • Mechanism: Triggers startElement, characters, and endElement sequentially. You must use boolean flags to track your position.
