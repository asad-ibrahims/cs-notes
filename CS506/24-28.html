Lecture 24: Web Applications & HTML Forms Basics

1. Web Architecture (Two-Tier vs Three-Tier)

Technical Definition: Web applications are built on Client-Server architecture. The Client (browser) sends an HTTP Request, and the Server sends an HTTP Response.

  • Two-Tier: Client directly communicates with the database server.
  • Three-Tier: Client communicates with a Web/Application Server, which then communicates with the Database. (Standard for modern web).
Roman Urdu Explanation: Jab aap browser mein `www.google.com` likhte hain, tou aapka browser (Client) ek Request bhejta hai Google ke Server ko. Server usay process karta hai aur wapas HTML bhejta hai jise Response kehte hain. 3-Tier architecture mein beech mein Web Server (jaise Tomcat) hota hai jo security aur logic handle karta hai taake database seedha expose na ho.

2. HTTP Protocol: GET vs POST

HTTP is the protocol used for transferring web pages. It provides two main methods to send data to the server:

Feature GET Method POST Method
Data Location Appended to the URL (Visible). Sent inside the HTTP message body (Hidden).
Data Limit Limited data (depends on max URL length). Unlimited data (ideal for large forms/files).
Security Insecure (Passwords are visible in URL). More secure (Data not visible in URL).

3. HTML Forms (Structure for User Input)

What is it? The HTML <form> element is used to collect user input (like login details, searches) and send it to a backend server.

HTML 
<form action="LoginServlet" method="POST">
    <!-- Input element for Text -->
    <label>Username:</label>
    <input type="text" name="uname"> <br>
    
    <!-- Input element for Password -->
    <label>Password:</label>
    <input type="password" name="pwd"> <br>
    
    <!-- Submit Button -->
    <input type="submit" value="Login">
</form>

Explanation of HTML Form:

  • <form>: The container for input elements.
  • action="LoginServlet": Crucial attribute. This tells the browser *WHERE* to send the data when the submit button is clicked. In this case, it goes to a Java Servlet named "LoginServlet".
  • method="POST": Tells the browser *HOW* to send the data. Since it's a login form, POST hides the password from the URL.
  • name="uname": Crucial attribute. The Java server uses this exact name to extract the value the user typed.
  • <input type="submit">: A special button that automatically packages all form data and sends the HTTP Request to the action URL.

Quick Revision - Lecture 24

  • Client-Server: Web apps work on HTTP Request & Response.
  • GET: Data visible in URL. Used for fetching/searching.
  • POST: Data hidden in body. Used for sensitive data/submitting.
  • HTML action: Destination URL for form data.
  • HTML name: Identifier for input fields used by the backend.

Lecture 25: Introduction to Servlets & Life Cycle

1. What is a Servlet?

Technical Definition: A Servlet is a Java technology used to create Web Applications. It is a Java class that resides and executes on a Web Server to process HTTP requests and generate dynamic web pages (usually HTML) as HTTP responses.

Roman Urdu Explanation: HTML sirf static (fixed) pages banata hai. Agar humein aisi website chahiye jahan user login kare, database se data aaye (Dynamic Web Page), tou humein server par logic likhni parti hai. Servlet darasal ek Java ka program hai jo Web Server (jaise Apache Tomcat) ke andar chalta hai. Ye HTML form se data leta hai, process karta hai, aur naya HTML page bana kar wapas bhej deta hai.

2. Web Container (Tomcat)

A Web Container (Servlet Container) is a part of a Web Server that interacts with the Servlets. The most famous one is Apache Tomcat. It manages the Servlet's life cycle, URL mapping, and handles the raw HTTP socket connections.

3. Servlet Life Cycle (Exam Favorite)

Just like Applets, Servlets do not have a main() method. The Web Container (Tomcat) manages them through three major methods:

1. init()
2. service()
3. destroy()
Method When is it called? Roman Urdu
init() Called exactly ONCE when the Servlet is first loaded into memory. Sirf zindagi mein ek dafa call hota hai, database connection waghera setup karne ke liye.
service() Called EVERY TIME a new request comes from a client. Har dafa jab koi user button click karta hai ya URL hit karta hai, yeh call hota hai form data process karne ke liye.
destroy() Called exactly ONCE when the server is shutting down or unloading the servlet. Server band hone se pehle resources (memory/connections) ko free karne ke liye call hota hai.
Important Rule:

Unlike old CGI (Common Gateway Interface) scripts that created a new heavy process for every request, Servlets create a new Thread for every request. This makes Servlets very fast and highly scalable.

Quick Revision - Lecture 25

  • Servlet: Java program running on a server to generate dynamic content.
  • Tomcat: The Web Container that runs and manages Servlets.
  • No Main Method: Servlets are managed by the container.
  • Life Cycle: init() -> service() -> destroy().

Lecture 26: Processing HTML Forms with Servlets

Relationship Check:
HTML creates the Form (Structure & UI).
Servlet (Java) reads the Form data, applies logic, and sends back a response.

1. HttpServlet and Methods

To create a Servlet, your Java class must extend HttpServlet. Instead of directly overriding service(), we usually override HTTP-specific methods:

  • doGet(HttpServletRequest req, HttpServletResponse res): Called if HTML form method was GET.
  • doPost(HttpServletRequest req, HttpServletResponse res): Called if HTML form method was POST.

2. Reading HTML Form Data in Java

When a client submits an HTML form, Tomcat bundles all the data into the HttpServletRequest object. We use request.getParameter("html_name_attribute") to extract it.

Roman Urdu Explanation: HTML form mein jis input field ka jo name="" rakha tha, Servlet usi naam ko istemal kar ke request.getParameter() ke zariye uski value nikalta hai. Har value String format mein aati hai.
Java 
import java.io.*;
import javax.servlet.*;
import javax.servlet.http.*;

// 1. Extend HttpServlet
public class LoginServlet extends HttpServlet {
    
    // 2. Override doPost because HTML form used method="POST"
    public void doPost(HttpServletRequest request, HttpServletResponse response) 
            throws ServletException, IOException {
        
        // 3. Read data sent by the HTML form
        // "uname" and "pwd" must match the name="" in HTML exactly
        String username = request.getParameter("uname");
        String password = request.getParameter("pwd");
        
        // 4. Set the content type of our response to HTML
        response.setContentType("text/html");
        
        // 5. Get PrintWriter to write HTML directly to the browser
        PrintWriter out = response.getWriter();
        
        // 6. Generate Dynamic HTML Response
        out.println("<html><body>");
        if(username.equals("admin") && password.equals("123")) {
            out.println("<h1>Welcome, " + username + "!</h1>");
        } else {
            out.println("<h1 style='color:red;'>Login Failed!</h1>");
        }
        out.println("</body></html>");
    }
}

Explanation of the Code:

  • HttpServletRequest: Contains everything the browser sent (parameters, IP, browser info).
  • HttpServletResponse: Used to send data BACK to the browser.
  • getParameter("uname"): Fetches the value entered by the user in the text box named "uname".
  • setContentType("text/html"): Tells the browser "Hey, I am sending you HTML code, so render it as a webpage, don't just show plain text."
  • PrintWriter out = response.getWriter(): Creates an output stream. Whatever we out.println() will be sent directly to the user's browser.
Common Mistakes:
  • Spelling mistake inside getParameter(). If the HTML has name="user" and you type getParameter("usr"), it will return null and crash your program (NullPointerException).
  • Forgetting to set response.setContentType("text/html"). The browser might download the response as a file instead of displaying it.

Quick Revision - Lecture 26

  • HttpServlet: Base class for web Servlets.
  • doGet / doPost: Methods to handle GET and POST requests.
  • request.getParameter("name"): Fetches form data. ALWAYS returns a String.
  • response.setContentType(): Defines MIME type (e.g., "text/html").
  • PrintWriter: Used to write HTML response to the client.

Lecture 27: Request Dispatching & Redirecting

1. What is Request Dispatching?

Technical Definition: Sometimes, a single Servlet cannot finish a request. It needs help from another Servlet or wants to send the user to an HTML/JSP page. Request Dispatching transfers the control from the current Servlet to another resource (HTML, JSP, or another Servlet) on the same server.

Roman Urdu Explanation: Agar Servlet ne login check kiya aur password theek nikla, tou Servlet khud naya bada HTML page generate (print) karne ke bajaye, request ko ek pehle se bane hue HTML page ki taraf "Forward" kar deta hai. Isse code clean rehta hai (Business Logic Java mein, Design HTML mein).

2. RequestDispatcher: forward() vs include()

The RequestDispatcher interface provides two main methods:

  • forward(request, response): Stops execution of the current servlet and permanently passes the request to another page. The user sees the output of the *second* page.
  • include(request, response): Temporarily borrows the output of another page, includes it in its own output, and then continues execution. Useful for adding a common header/footer HTML to all pages.
Java Syntax 
// 1. Get the dispatcher for a specific HTML page
RequestDispatcher rd = request.getRequestDispatcher("welcome.html");

// 2. Forward the request
rd.forward(request, response);

3. sendRedirect (Different from Forward)

response.sendRedirect("URL") tells the client's browser to make a brand NEW request to a different URL. It can redirect to a completely different website (e.g., google.com), unlike RequestDispatcher which only works on the same server.

Feature RequestDispatcher (forward) sendRedirect
Who handles it? Server handles it internally. Browser is told to make a new request.
URL in Browser URL does NOT change. URL CHANGES to the new location.
Speed Faster (internal). Slower (requires extra network round-trip).

Quick Revision - Lecture 27

  • RequestDispatcher: Moves processing to another resource on the same server.
  • forward(): Complete handover. Current servlet stops.
  • include(): Merges output from another resource.
  • sendRedirect(): Client-side redirect. Changes browser URL. Can go to external sites.

Technical Definition: HTTP is a stateless protocol. This means every request is independent. The server does not remember anything from the previous request. If you log in on page 1 and go to page 2, the server forgets who you are.
