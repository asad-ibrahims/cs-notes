Lecture 19: How to Animate? (Threads & Multithreading)

1. What is Multithreading & Animation?

Technical Definition: A thread is a lightweight sub-process or the smallest unit of processing. Multithreading is the concurrent execution of two or more threads to maximize CPU utilization. In Java GUIs, animation is achieved by continuously updating graphics in an infinite loop running on a separate thread to prevent UI freezing.

Roman Urdu Explanation: Java ka program default tareeqay se ek waqt mein ek hi kaam karta hai (Single-threaded). Agar humein GUI mein koi cheez move karni ho (Animation), tou uske liye humein ek infinite `while` loop lagana parta hai. Agar hum yeh loop 'Main Thread' par lagayenge, tou poori screen hang ho jayegi (buttons click nahi honge). Is maslay ko hal karne ke liye hum ek naya "Thread" (background worker) banate hain jo sirf animation ka kaam karta hai.

2. How does it work? (Runnable Interface)

To create a thread, we generally implement the Runnable interface and override its run() method. To create animation, we use Thread.sleep() to add a delay between drawing frames.

class MyClass implements Runnable {
    public void run() {
        // Code that will run in background
    }
}

3. Code Example & Explanation

public class AnimationTask implements Runnable {
    
    // 1. run() method is mandatory when implementing Runnable
    public void run() {
        while(true) { // 2. Infinite loop for continuous animation
            
            updatePosition(); // 3. Change coordinates
            repaint();        // 4. Redraw the screen
            
            try {
                // 5. Pause the thread for 50 milliseconds
                Thread.sleep(50); 
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
    }
}

Explanation:

  • implements Runnable: Indicates this class can be executed by a Thread.
  • public void run(): The starting point for the new thread. The logic goes here.
  • repaint(): A standard Java method that asks the JVM to redraw the GUI components.
  • Thread.sleep(50): Halts execution for 50ms. This prevents the animation from moving so fast that the human eye can't see it.
  • try-catch block: sleep() can throw an InterruptedException, so we must handle it using try-catch.
Common Mistakes / Rules:
  • Rule: You CANNOT call the run() method directly. You must create a Thread object and call start() (e.g., Thread t = new Thread(new AnimationTask()); t.start();). Calling run() directly executes it in the current thread, defeating the purpose!
  • Mistake: Forgetting the try/catch block around Thread.sleep(). The compiler will give an error.

Quick Revision - Lecture 19

  • Thread: Lightweight independent path of execution.
  • Runnable: Interface used to define thread behavior.
  • run(): Method where thread logic is placed.
  • start(): Method used to begin thread execution.
  • sleep(): Pauses thread. Crucial for controlling animation speed.

Lecture 20: Introduction to Applets

1. What is an Applet?

Technical Definition: An Applet is a special type of Java program that is embedded in an HTML page to generate dynamic content. It runs inside the web browser and works on the client-side.

Roman Urdu Explanation: Normal Java applications (Desktop apps) ko run karne ke liye main() method zaroori hota hai. Lekin Applet ek aisi Java application hai jo seedha aapke HTML Web Page (browser) ke andar chalti hai. Isme main() method nahi hota kyunke browser khud iski zindagi (life cycle) ko control karta hai.

2. The HTML <applet> Tag (HTML Integration)

Because Applets run inside browsers, we use a specific HTML tag to embed them in a webpage. (Note: This tag is deprecated in modern HTML5 but is heavily featured in the CS506 syllabus).

<applet code="ClassName.class" width="pixelValue" height="pixelValue">
</applet> 
<html>
<head>
    <title>My First Applet Page</title>
</head>
<body>
    <h1>Welcome to Java Applets</h1>
    
    <!-- Applet Integration -->
    <applet code="HelloWorldApplet.class" width="400" height="300">
        Alt Text: Browser does not support Applets.
    </applet>
</body>
</html>

HTML Tag Explanation:

  • <applet>: The HTML element used to embed the Java program.
  • code Attribute: Specifies the name of the compiled Java file (e.g., .class file) that contains the applet logic.
  • width & height: Defines the dimensions (in pixels) of the applet window displayed on the webpage.

3. Applet Life Cycle (Crucial for Exams)

Applets do not have a main() method. The browser calls specific methods at specific times.

Method When is it called? Roman Urdu
init() Once, when the applet is first loaded. Jab browser pehli dafa applet load karta hai, initialization (variables setup) ke liye.
start() Whenever the applet becomes visible (e.g., maximizing window or revisiting page). Jab user us page par aata hai aur applet screen par nazar aata hai.
paint(Graphics g) Whenever the applet needs to be redrawn. Shapes, lines, ya text draw karne ke liye. Yeh baar baar call ho sakta hai.
stop() When the applet becomes hidden (e.g., changing tabs). Jab user kisi aur tab ya page par chala jata hai tou execution rokne ke liye.
destroy() Once, when the browser is closed. Jab browser close kiya jata hai, memory azaad (free) karne ke liye.
Important Rules:
  • Applet class must inherit from java.applet.Applet.
  • The class must be declared public so the browser can access it.

Quick Revision - Lecture 20

  • No Main Method: Applets rely on the browser for execution.
  • Applet Tag: <applet code="X.class" width="200" height="200"></applet>
  • Life Cycle Order: init() -> start() -> paint() -> stop() -> destroy()

Lecture 21: Introduction to Sockets (Networking)

1. What is Socket Programming?

Technical Definition: A socket is an endpoint for a two-way communication link between two programs running on the network. Socket programming is a way of connecting two nodes (Client and Server) on a network to communicate with each other.

Roman Urdu Explanation: Jab do computers ne aapas mein baat karni ho (jaise chatting app ya game), tou wo "Sockets" ka istemaal karte hain. Server computer ek specific darwaze (Port) par khara ho kar intezar karta hai. Client computer Server ke IP Address aur Port Number ko use kar ke connection request bhejta hai. Jab connection ban jata hai, dono ek doosre ko data bhej sakte hain.

2. Core Networking Concepts

  • IP Address: The unique address of a computer on a network (e.g., 192.168.1.5 or localhost / 127.0.0.1 for same machine).
  • Port: A logical channel on a computer. (e.g., Port 80 for Web/HTTP, Port 21 for FTP). Range is 0-65535.

3. Code Example: Echo Server & Client

Server Side (EchoServer)

import java.net.*;
import java.io.*;

public class Server {
    public static void main(String[] args) throws Exception {
        // 1. Create a ServerSocket listening on port 9999
        ServerSocket ss = new ServerSocket(9999);
        System.out.println("Server is waiting for client...");
        
        // 2. Wait and ACCEPT the incoming connection
        Socket s = ss.accept(); 
        System.out.println("Client Connected!");
        
        // 3. Setup Streams to receive and send data
        InputStream is = s.getInputStream();
        OutputStream os = s.getOutputStream();
        
        // (Logic to read/write data goes here)
        
        s.close(); // 4. Close connection
    }
}

Client Side (EchoClient)

import java.net.*;
import java.io.*;

public class Client {
    public static void main(String[] args) throws Exception {
        // 1. Create a socket connecting to server's IP and Port
        Socket s = new Socket("localhost", 9999);
        
        // 2. Setup streams
        InputStream is = s.getInputStream();
        OutputStream os = s.getOutputStream();
        
        // (Logic to send/receive data goes here)
        
        s.close();
    }
}

Explanation:

  • ServerSocket(port): Used by the server to open a port and wait.
  • accept(): This is a blocking method. The server stops on this line and waits until a client connects. It returns a Socket object.
  • Socket(ip, port): Used by the client to request a connection to the server.
  • getInputStream() / getOutputStream(): Once connected, these streams act as the pipeline for data to travel back and forth.
Common Mistakes / Rules:
  • Rule: The Server must be started BEFORE the Client. If the client tries to connect to an offline server, it throws ConnectException.
  • Mistake: Trying to use a Port number below 1024. These are reserved for system services. Use high numbers like 8000, 9999, etc.

Quick Revision - Lecture 21

  • Socket: Endpoint of communication.
  • ServerSocket: Waits for client requests on the server side.
  • accept(): Blocks execution until a client connects.
  • localhost: Refers to the current machine (127.0.0.1).

Lecture 22: Object Serialization

1. What is Serialization?

Technical Definition: Serialization is the process of converting an object's state (its variables and data) into a byte stream so that it can be reverted back into a copy of the object later. The reverse process is called Deserialization.

Roman Urdu Explanation: Jab aapka Java program band hota hai, tou uske andar banay gaye tamam Objects memory (RAM) se delete ho jate hain. Agar aap chahte hain ke Object ka data kisi file mein save ho jaye (taake baad mein load kar sakein) ya network ke zariye doosre computer par bheja jaye, tou aapko us Object ko bytes (0s aur 1s) mein convert karna parta hai. Is conversion ke amal ko Serialization kehte hain.

2. How does it work? (Serializable Interface)

For a class to be serialized, it MUST implement the java.io.Serializable interface. This is a Marker Interface (it contains no methods). It just gives a hint to the JVM that this class is allowed to be serialized.

import java.io.Serializable;

class Person implements Serializable {
    String name;
    int age;
}

3. Code Example: Saving an Object to a File

import java.io.*;

// 1. Must implement Serializable
class Student implements Serializable { 
    String name = "Ali";
    int id = 101;
}

public class SerializeTest {
    public static void main(String[] args) {
        try {
            Student s1 = new Student();
            
            // 2. Setup output streams pointing to a file
            FileOutputStream fos = new FileOutputStream("studentData.ser");
            ObjectOutputStream oos = new ObjectOutputStream(fos);
            
            // 3. Write the whole object at once!
            oos.writeObject(s1); 
            
            oos.close();
            System.out.println("Object Saved!");
            
        } catch(IOException e) {
            e.printStackTrace();
        }
    }
}

Explanation:

  • implements Serializable: Without this, Java will throw NotSerializableException.
  • FileOutputStream: Prepares a file to write plain bytes.
  • ObjectOutputStream: Wraps around FileOutputStream to provide the magic writeObject() method which converts the object to bytes.
  • writeObject(): Actually performs the serialization.
Important Rules:
  • Rule (Exam Point): What is a Marker Interface? An interface with ZERO methods. Example: Serializable.
  • transient Keyword: If you have a variable (like a password) that you DO NOT want to save/serialize, put the keyword transient before it (e.g., transient String password;).

Quick Revision - Lecture 22

  • Serialization: Object state to Byte Stream.
  • Deserialization: Byte Stream back to Object.
  • Serializable: Marker interface required to allow serialization.
  • ObjectOutputStream: Used to write objects (writeObject).
  • ObjectInputStream: Used to read objects (readObject).

Lecture 23: Multithreaded Server

1. The Problem with Single-Threaded Servers

The Server we created in Lecture 21 could only handle ONE client at a time. If Client A connects, the server processes Client A. If Client B tries to connect during this time, Client B must wait. This is a severe bottleneck.

Roman Urdu Explanation: Lecture 21 wale server ki misaal aisi hai jaise bank mein sirf ek hi cashier ho. Jab tak wo ek customer ko deal kar raha hai, baqi sab line mein wait karenge. Multithreaded server ka matlab hai ke bank manager (Main Server Thread) jaise hi naye customer ko dekhta hai, wo ek naya cashier (New Thread) assign kar deta hai us customer ke liye. Aur khud wapas gate par aa jata hai naye logo ka wait karne ke liye.

2. The Solution: Multithreading

We combine Sockets (Lecture 21) with Threads (Lecture 19). For every client that connects, the server spawns a new Thread to handle that specific client, allowing the main server thread to go back to accept() immediately.

3. Code Example & Logic

import java.net.*;
import java.io.*;

// 1. ClientHandler class runs as a Thread for each client
class ClientHandler implements Runnable {
    Socket clientSocket;
    
    // Constructor receives the specific socket
    public ClientHandler(Socket s) {
        this.clientSocket = s;
    }
    
    public void run() {
        try {
            // Logic to talk to this specific client
            System.out.println("Processing client request...");
            clientSocket.close();
        } catch (Exception e) {}
    }
}

public class MultiServer {
    public static void main(String[] args) throws Exception {
        ServerSocket ss = new ServerSocket(9999);
        System.out.println("Server Started...");
        
        // 2. Infinite Loop to accept multiple clients
        while(true) {
            Socket s = ss.accept(); // Blocks until a client connects
            
            // 3. Once connected, pass socket to a new Thread and start it
            ClientHandler handler = new ClientHandler(s);
            Thread t = new Thread(handler);
            t.start(); 
            
            // Loop goes back to accept() immediately!
        }
    }
}

Explanation:

  • while(true): Keeps the server running forever.
  • accept(): Waits for a client. When a client connects, it returns a Socket.
  • new ClientHandler(s): We pass the newly created Socket to our custom Runnable class.
  • t.start(): A new background thread begins talking to the client. The main while loop instantly loops back and waits for the next client at accept() without being blocked by data processing.

Quick Revision - Lecture 23

  • Problem: accept() and I/O streams are blocking. Single threads halt the entire server.
  • Solution: A while(true) loop containing accept(), followed immediately by starting a new Thread.
  • Architecture: 1 Main Thread (Listener) + N Worker Threads (1 for each connected Client).
