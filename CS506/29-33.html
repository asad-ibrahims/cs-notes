Lecture 29: Introduction to JSP (Java Server Pages)

1. What is JSP and Why is it used?

Technical Definition: Java Server Pages (JSP) is a server-side technology used to create dynamic web pages. It allows developers to embed Java code directly into HTML pages. JSP is built on top of the Servlet API.

Why is it used? In pure Servlets, developers had to write HTML code inside Java strings (e.g., out.println("<html>")). This made designing and maintaining UI extremely difficult. JSP solves this by reversing the process: you write standard HTML and insert Java only where dynamic data is needed.

Roman Urdu Explanation: Servlets mein masla yeh tha ke humein Java code ke andar HTML likhna parta tha. Agar web designer ko UI change karna ho tou usay Java code mein modification karni parti thi. JSP ne isko asaan kar diya: ab hum normal HTML page banate hain aur jahan calculation ya database ka data dikhana ho, wahan hum thora sa Java code daal dete hain.

2. The JSP Lifecycle (How it works)

Behind the scenes, the Web Container (like Tomcat) automatically converts your JSP file into a Servlet.

  1. Translation Phase: The container translates the .jsp file into a .java Servlet file.
  2. Compilation Phase: The .java file is compiled into a .class file.
  3. Initialization: jspInit() method is called.
  4. Execution: _jspService() method handles the actual HTTP Request/Response.
  5. Destruction: jspDestroy() is called when the JSP is removed from memory.

3. Basic Structure / Comparison

Servlet Approach (Hard) JSP Approach (Easy) 
out.println("<html>");
out.println("<body>");
out.println("<h1>" + name + "</h1>");
out.println("</body>");
out.println("</html>");
 
<html>
<body>
  <h1><%= name %></h1>
</body>
</html>
Important Rules: JSP files must be saved with the .jsp extension and must be placed in a web directory that the server can access (like the webapps folder in Tomcat).

Quick Revision - Lecture 29

  • JSP: Java Server Pages. HTML with embedded Java.
  • Purpose: Separates presentation (HTML) from business logic (Java).
  • Internal Working: Every JSP is ultimately converted into a Servlet by the server.
  • Lifecycle Methods: jspInit(), _jspService(), jspDestroy().

Lecture 30: JSP Scripting Elements

1. What are Scripting Elements?

Technical Definition: Scripting elements are specific tags in JSP that allow you to insert Java code into the HTML page. The JSP engine reads these tags and executes the Java code during the page translation phase.

Roman Urdu Explanation: HTML page ko yeh kaise pata chalega ke kahan HTML khatam ho raha hai aur kahan Java shuru ho rahi hai? Is maqsad ke liye JSP mein kuch special tags banaye gaye hain jinhein Scripting Elements kehte hain. In tags ke andar likha hua code Java code samjha jata hai.

2. Types of Scripting Elements

A. Directives <%@ ... %>

Used to give special instructions to the JSP container (like importing Java packages).

Syntax: <%@ directive_name attribute="value" %>

Example: <%@ page import="java.util.Date" %>

B. Declarations <%! ... %>

Used to declare class-level variables or methods. These go outside the _jspService() method in the translated Servlet.

Syntax: <%! Java Code (Variable/Method) %>

Example: <%! int clickCount = 0; %>

C. Scriptlets <% ... %>

Used to write regular Java logic (if/else, loops). The code goes directly inside the _jspService() method.

Syntax: <% standard java code statements %>

Example: <% int a = 5; out.print(a); %>

D. Expressions <%= ... %>

Used to print a Java variable or calculation directly to the HTML page. It automatically converts the result to a string.

Syntax: <%= Java Expression %>

Example: <h1>Hello <%= username %></h1>

3. Complete Example

<!-- 1. Directive: Importing ArrayList -->
<%@ page import="java.util.ArrayList" %>

<html>
<body>
    <!-- 2. Declaration: Declaring a method -->
    <%! 
        public int add(int a, int b) { 
            return a + b; 
        } 
    %>

    <h2>JSP Scripting Elements Demo</h2>
    
    <!-- 3. Scriptlet: Java logic -->
    <% 
        int x = 10;
        int y = 20;
        int sum = add(x, y); 
    %>

    <!-- 4. Expression: Printing Output -->
    <p>The sum of x and y is: <%= sum %></p>

</body>
</html>

Explanation:

  • <%@ page ... %> tells the server we need the ArrayList class.
  • <%! ... %> creates an add() function that can be used anywhere in the file.
  • <% ... %> declares variables and calls the add() function.
  • <%= sum %> prints the final result into the HTML paragraph.
Common Mistakes / Rules:
  • Mistake: Putting a semicolon (;) inside an Expression tag.
    ❌ <%= name; %> (Error!)
    ✅ <%= name %> (Correct!)
  • Rule: Variables declared in <%! %> (Declarations) are shared among all users (instance variables). Variables declared in <% %> (Scriptlets) are specific to one request (local variables).

Quick Revision - Lecture 30

  • <%@ ... %>: Directives (Imports, page config).
  • <%! ... %>: Declarations (Class-level methods/variables).
  • <% ... %>: Scriptlets (Local variables, loops, logic).
  • <%= ... %>: Expressions (Outputting values to HTML directly).

Lecture 31: JSP Implicit Objects

1. What are Implicit Objects?

Technical Definition: Implicit objects are pre-created Java objects provided by the JSP container automatically. Developers can use them inside scriptlets and expressions without having to write new ObjectName().

Roman Urdu Explanation: Normal Java mein kisi bhi class ka function use karne se pehle uska object banana parta hai (jaise Scanner sc = new Scanner()). JSP mein kuch cheezein itni common hain (jaise request receive karna, response bhejna, screen pe print karna) ke server unke objects khud pehle se bana kar humein de deta hai. In ready-made objects ko Implicit Objects kehte hain.

2. The 9 Implicit Objects (Crucial for Exams)

Object Name Java Class/Interface Purpose
request HttpServletRequest Gets input from the user (HTML forms, URL params).
response HttpServletResponse Sends output/redirects back to the user's browser.
out JspWriter Used to write text directly to the HTML page.
session HttpSession Stores data specific to a single user across multiple pages (e.g., Login state).
application ServletContext Stores data shared globally across all users in the application.
config ServletConfig Contains initialization parameters for the specific JSP page.
pageContext PageContext Provides access to all other implicit objects and manages page attributes.
page Object (this) Refers to the current JSP instance (rarely used).
exception Throwable Used for Error Handling. (Only available in pages marked as Error Pages).

3. Code Example using Implicit Objects

<html>
<body>
    <h2>Implicit Objects Example</h2>

    <%
        // 1. Using 'request' to get a value from a form submission
        String username = request.getParameter("uname");
        
        // 2. Using 'session' to save the username for later
        if (username != null) {
            session.setAttribute("savedUser", username);
        }
        
        // 3. Using 'out' to print a custom message inside the scriptlet
        out.println("<p>Checking login status...</p>");
    %>

    <!-- Accessing session data later using expression -->
    <p>Welcome back, <%= session.getAttribute("savedUser") %>!</p>

</body>
</html>

Explanation:

  • request.getParameter() reads the data sent by the browser. We didn't create request, it was provided automatically.
  • session.setAttribute() stores the user's name so it won't be forgotten if they click a link to another page.
  • out.println() writes HTML directly from the Java logic block.

Quick Revision - Lecture 31

  • Implicit Objects: Ready-to-use variables provided by Tomcat/Container.
  • Most Used: request, response, session, out.
  • exception: The only implicit object that is NOT available on every page by default. It requires isErrorPage="true".

Lecture 32: JSP Standard Actions

1. What are Standard Actions?

Technical Definition: JSP Standard Actions are XML-like tags built into JSP that control the behavior of the JSP engine. They are used for common tasks like including other files, forwarding requests, and interacting with JavaBeans without writing raw Java code.

Roman Urdu Explanation: JSP ka main maqsad HTML se Java code ko kam karna hai. Agar aapko ek page se doosre page par jana ho, ya ek common header file har page mein add karni ho, tou Java code (Scriptlet) likhne ke bajaye aap Action Tags use kar sakte hain. Inki shakal bilkul HTML tags jaisi hoti hai (jaise <jsp:include>) jo designers ke liye asaan hota hai.

2. Important Action Tags

A. <jsp:include>

Includes a static or dynamic file at request time. If the included file changes, the changes appear immediately without restarting.

<jsp:include page="header.jsp" />

B. <jsp:forward>

Forwards the user's request from the current JSP page to another JSP, Servlet, or HTML page. The URL in the browser does NOT change.

<jsp:forward page="login.jsp" />

C. <jsp:param>

Used inside <jsp:include> or <jsp:forward> to pass extra data to the target page.

<jsp:forward page="profile.jsp">
    <jsp:param name="status" value="success" />
</jsp:forward>

3. Action Tags vs Directives (Exam Question)

Feature <jsp:include> (Action Tag) <%@ include %> (Directive)
When does it happen? At Request time (when user visits the page). At Translation time (when JSP converts to Servlet).
Dynamic Updates? Yes, changes in the included file show immediately. No, changing the included file requires recompiling the main JSP.
Best For: Dynamic content (like menus, sidebars). Static content (like copyright footers, CSS links).
Syntax Rule: Standard Actions follow XML rules. This means every tag MUST be closed properly either like <jsp:forward> ... </jsp:forward> or self-closed like <jsp:include />.

Quick Revision - Lecture 32

  • Standard Actions: XML-styled tags to reduce Java code in JSP.
  • jsp:include: Request-time inclusion of files.
  • jsp:forward: Transfers processing to another page.
  • jsp:param: Sends parameters to the forwarded/included page.

Lecture 33: JavaBeans & JSP (The MVC Approach)

1. What is a JavaBean?

Technical Definition: A JavaBean is a standard, reusable Java class used to encapsulate many objects into a single object (the bean). In Web Development, it is used as a "Model" to hold data temporarily (like a Student's data) between the database and the JSP UI.

Roman Urdu Explanation: JavaBean koi nayi language ya technology nahi hai, yeh sirf ek simple Java class likhne ka standard tareeqa hai. Agar humare paas form mein 10 inputs hain (name, age, address, etc.), tou JSP mein 10 alag variables banane ke bajaye, hum ek "UserBean" class banate hain. Us class ka object saara data apne andar save kar leta hai. Yeh code ko saaf aur maintainable banata hai.

2. Rules to create a JavaBean

To qualify as a JavaBean, a Java class MUST follow three strict rules:

  1. It must have a public default (no-argument) constructor.
  2. All variables (attributes) must be private.
  3. It must have public Getter and Setter methods for all variables.
// EmployeeBean.java
public class EmployeeBean {
    private String name; // Private attribute

    public EmployeeBean() {} // No-arg constructor

    // Public Setter
    public void setName(String n) { this.name = n; }

    // Public Getter
    public String getName() { return this.name; }
}

3. Using JavaBeans in JSP (Action Tags)

JSP provides three special Standard Actions specifically to work with Beans without writing scriptlet Java code.

1. <jsp:useBean>

Creates an object (instance) of the JavaBean class.

<jsp:useBean id="emp" class="EmployeeBean" scope="request" />

(Equivalent Java: EmployeeBean emp = new EmployeeBean();)

2. <jsp:setProperty>

Sets the value of a property inside the Bean.

<jsp:setProperty name="emp" property="name" value="Ali" />

(Equivalent Java: emp.setName("Ali");)

3. <jsp:getProperty>

Gets the value from the Bean and prints it on the screen.

<jsp:getProperty name="emp" property="name" />

(Equivalent Java: out.print(emp.getName());)

4. Complete Example

<!-- 1. Instantiate the Bean -->
<jsp:useBean id="user" class="MyPackage.UserBean" />

<!-- 2. Suppose a form was submitted, we capture 'username' -->
<jsp:setProperty name="user" property="name" param="username" />

<html>
<body>
    <h2>JavaBeans Demo</h2>
    
    <!-- 3. Display the stored data -->
    <p>The logged-in user is: 
       <strong> <jsp:getProperty name="user" property="name" /> </strong>
    </p>
</body>
</html>

Explanation:

  • useBean creates the object named "user".
  • setProperty looks for an HTML form parameter called "username" and automatically passes it to the Bean's setName() method.
  • getProperty calls the Bean's getName() method and prints the output in the paragraph tag.
Magic Syntax Trick:
If your HTML form input name attributes exactly match the JavaBean property names, you can use a shortcut to set all properties at once:
<jsp:setProperty name="user" property="*" />

Quick Revision - Lecture 33

  • JavaBean: A reusable Java class with private fields, public getters/setters, and a no-arg constructor.
  • useBean: Action tag to instantiate a Bean.
  • setProperty: Action tag to call a setter method.
  • getProperty: Action tag to call a getter method and display data.
  • MVC Basics: Model = JavaBean, View = JSP, Controller = Servlet.
