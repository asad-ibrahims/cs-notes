Lecture 19: Dynamic Programming & Edit Distance (Intro)

What is Dynamic Programming (DP)?

Technical Definition: Dynamic Programming is an algorithmic technique for solving an optimization problem by breaking it down into simpler overlapping subproblems and storing the solutions to these subproblems to avoid redundant computations (a process called Memoization or Tabulation).
Roman Urdu: DP ek aisi technique hai jahan hum ek baday aur mushkil problem ko chotay hisso (subproblems) mein divide karte hain. Greedy approach ki tarah nahi, balki yahan subproblems aapas mein overlap karte hain (yaani ek subproblem baar baar use hota hai). Hum un chotay problems ka answer ek table/array mein save kar lete hain taake dobara calculate na karna pare. Is se time bach jata hai.

Why do we need it?

Simple recursion often calculates the same subproblem multiple times, leading to Exponential time complexity O(2n). DP saves past results, converting exponential time to polynomial time like O(n2) or O(n).

Problem Statement: The Edit Distance Problem

Given two strings, what is the minimum number of operations required to transform the first string into the second string?

Operations allowed:
  • Insertion: Add a new character.
  • Deletion: Remove a character.
  • Replacement/Substitution: Replace one character with another.
Roman Urdu: Farz karein aapke paas do words hain. Aapko pehle word ko badal kar dusra word banana hai. Aap 3 kaam kar sakte hain: koi naya letter daalna (Insert), koi letter delete karna, ya kisi letter ko replace karna. Hum chahte hain ke kam se kam steps mein yeh kaam ho jaye. Is minimum cost ko "Edit Distance" kehte hain.

⚡ Lecture 19 - Quick Revision

  • Core Concept: Dynamic Programming (DP) is for overlapping subproblems + optimal substructure.
  • Difference from Divide & Conquer: D&C divides into independent subproblems. DP handles overlapping subproblems.
  • Edit Distance: Minimum cost to convert String A to String B using Insert, Delete, and Replace.
  • Common Mistake: Thinking DP always uses recursion. DP can be Bottom-Up (Tabulation using loops) which is usually better for saving memory overhead.

Lecture 20: Edit Distance Algorithm & Trace

Algorithm Idea

Roman Urdu: Edit distance ko solve karne ke liye hum ek 2D array (Table) `E` banate hain. Agar pehli string `x` ki length `m` hai, aur dusri string `y` ki length `n` hai, toh matrix ka size `(m+1) x (n+1)` hoga. Hum table ko row-by-row fill karte hain. Kisi bhi cell `E[i,j]` ka matlab hai ke `x` ke pehle `i` characters ko `y` ke pehle `j` characters mein badalne ki minimum cost kya hai.

The Recursive Formula (Heart of DP)

To find the value of E[i, j], we take the minimum of three choices:

E[i, j] = min( E[i-1, j] + 1, // Deletion E[i, j-1] + 1, // Insertion E[i-1, j-1] + diff // Replacement (diff = 0 if chars match, 1 if they don't) )

Step-by-Step Example: "BAT" to "BIT"

Let string 1 = "BAT" (length 3), String 2 = "BIT" (length 3). Matrix size = 4x4.

1
Initialization: Row 0 and Col 0 represent comparing with an empty string. If you have "BAT" and want an empty string, you need 3 deletions (cost=3). So, initialize row 0 and col 0 with 0, 1, 2, 3...
2
Filling Cell [1,1] (B vs B): Chars match. diff = 0. Min of (Insert: 1+1=2, Delete: 1+1=2, Replace: 0+0=0). Value is 0.
3
Filling Cell [2,2] (A vs I): Chars don't match. diff = 1. Value becomes min of neighbors + 1.
empty (0) B (1) I (2) T (3)
empty (0) 0 1 2 3
B (1) 1 0 1 2
A (2) 2 1 1 2
T (3) 3 2 2 1

The final answer is at the bottom right cell E[m, n], which is 1 (Just replace 'A' with 'I').

Algorithm Complexity

O(m × n)
Time Complexity: We fill a table of size `m` by `n`. Each cell takes constant time `O(1)` to compute the minimum of 3 values. Total time is `O(m*n)`.
Space Complexity: `O(m*n)` to store the 2D table.
Roman Urdu: Agar `x` ki length `m` hai aur `y` ki `n`, toh humein poori table fill karni hai jisme `m*n` boxes hain. Har box fill karne mein fixed chota sa time lagta hai, isiliye total time `m*n` hua.

⚡ Lecture 20 - Quick Revision

  • Equation: min(delete, insert, replace) from previous subproblems.
  • Base Cases: Comparing with an empty string means cost is equal to the length of the current string.
  • Complexity: Time O(mn), Space O(mn).
  • What must be remembered: If characters match, the replace cost (diagonal step) is +0. If they don't, it is +1.

Lecture 21: Matrix Chain Multiplication (Concept)

What is it?

Technical Definition: The Matrix Chain Multiplication problem is an optimization problem that finds the most efficient way to multiply a given sequence of matrices. The problem is not actually to perform the multiplications, but merely to decide the sequence of the matrix multiplications involved.

Matrix multiplication is associative: (A × B) × C = A × (B × C). The final result is the same, but the number of scalar operations (cost) depends heavily on the parenthesization order.

Roman Urdu: Jab humein 3 ya us se zyada matrices ko multiply karna ho, toh bracket lagane ke tareeqay se answer toh same aata hai, lekin calculations ki tadaad bohat differ kar sakti hai. Humara maqsad hai aisi brackets lagana jis se total multiplications sab se kam ho jayen.

Basic Rule of Matrix Multiplication

If Matrix A has dimensions p × q and Matrix B has dimensions q × r, they can be multiplied.

The resulting matrix C has dimensions p × r.

Total number of scalar multiplications required = p × q × r.

Simple Example of The Problem

Consider 3 matrices:

  • A: 10 × 100
  • B: 100 × 5
  • C: 5 × 50

Case 1: (A × B) × C

  • A×B cost = 10 × 100 × 5 = 5,000. Result is 10×5 matrix.
  • (AB)×C cost = 10 × 5 × 50 = 2,500.
  • Total Cost = 5,000 + 2,500 = 7,500 operations.

Case 2: A × (B × C)

  • B×C cost = 100 × 5 × 50 = 25,000. Result is 100×50 matrix.
  • A×(BC) cost = 10 × 100 × 50 = 50,000.
  • Total Cost = 25,000 + 50,000 = 75,000 operations.
Roman Urdu: Dekhein! Sirf brackets badalne se Case 1 (7,500) Case 2 (75,000) se 10 guna zyada tez hai. Isliye correct order find karna zaroori hai.

⚡ Lecture 21 - Quick Revision

  • Problem: Find the optimal parenthesization order, NOT the actual multiplied matrix.
  • Cost Formula: Multiplying a (p×q) matrix with a (q×r) matrix takes p*q*r multiplications.
  • Brute Force fails: The number of ways to parenthesize `n` matrices is the Catalan number, which grows exponentially O(4n/n1.5). Hence, we need DP!

Lecture 22: Matrix Chain DP & Knapsack Intro

Matrix Chain DP Algorithm Idea

Let m[i, j] be the minimum number of scalar multiplications needed to compute the matrix product from Ai to Aj.

Roman Urdu: Hum check karte hain ke matrices ke sequence ko kahan se split (todna) faidamand hoga. Farz karein `k` wo point hai jahan hum split lagate hain (i <= k < j). Hum har possible `k` ke liye cost nikalte hain aur sab se choti cost ko save kar lete hain.
// Recurrence Relation: m[i, j] = 0 if i == j // Ek matrix ko multiply karne ki cost 0 hoti hai m[i, j] = min( m[i,k] + m[k+1,j] + p_{i-1}*p_k*p_j ) for k = i to j-1

Complexity of Matrix Chain DP

O(n3)
Time Complexity: There are O(n2) subproblems (cells in the upper triangle of the table). For each cell, we test O(n) possible splitting points `k`. Total time is O(n3).
Space Complexity: O(n2) for the table `m[i,j]`.
Roman Urdu: Table mein n*n cells hain. Aur har cell ko fill karne ke liye hum loop lagate hain `k` par (jo `n` tak ja sakta hai). Isliye total time `n * n * n = n^3` ho jata hai.

Introduction to The Knapsack Problem

The Scenario: A thief robs a store and has a knapsack (bag) that can carry a maximum weight W. There are n items in the store, each with a weight wi and a value (price) vi. The thief wants to maximize the total value stolen without exceeding the weight limit.

Two Variations of Knapsack

  1. Fractional Knapsack: The thief can take fractions of an item (like taking 1 kg of sugar from a 5 kg bag).
    Solution: Greedy Algorithm works here. Calculate Value/Weight ratio, sort, and take the highest ratio items first.
  2. 0/1 Knapsack: The item is indivisible. The thief must either take the whole item (1) or leave it (0). (Like a TV or a laptop).
    Solution: Greedy fails. Dynamic Programming is required.
Roman Urdu: Agar saman tor kar (fractions) le jaya ja sake (jese cheeni, daal), toh Greedy best hai (mehngi cheez pehle uthao). Lekin agar cheez solid hai (jese laptop), to Greedy fail ho jati hai, kyunke ho sakta hai ek bhari mehngi cheez lene se bag bhar jaye aur aap zyada faide wali choti 2-3 cheezein na le sakein. Wahan humein DP lagani parti hai.

⚡ Lecture 22 - Quick Revision

  • Matrix DP State: `m[i,j]` stores min cost to multiply matrices i to j.
  • Matrix Split: We check all `k` and take the minimum. Time Complexity is O(n³).
  • Knapsack Problem: Maximize value within weight limit W.
  • Fractional = Greedy: Sort by Value/Weight ratio. O(n log n).
  • 0/1 Knapsack = DP: Cannot take partial items. Greedy strategy does not guarantee an optimal solution.

Lecture 23: 0/1 Knapsack Problem (DP Approach)

The DP Idea

We create a 2D array V[i, w]. It stores the maximum value that can be obtained using the first i items, given a weight limit w.

Roman Urdu: Har item par hamare paas 2 choices hoti hain: 1. Leave it: Item bag mein na daalein. Total value utni hi rahegi jitni pichle items se thi. 2. Take it: Item bag mein daal lein. Humein is item ki value mil jayegi, lekin bag ki capacity `w_i` se kam ho jayegi. Hum in dono choices mein se jo zyada faida (max) de, usko select karte hain.

The Recursive Formula

if w_i > w (Item is heavier than current limit) : V[i, w] = V[i-1, w] // Have to leave it else : V[i, w] = max( V[i-1, w], // Case 1: Leave item V[i-1, w - w_i] + v_i // Case 2: Take item )

Step-by-Step Example

Max Capacity (W) = 5. Items (n) = 3

  • Item 1: Weight = 1, Value = 60
  • Item 2: Weight = 2, Value = 100
  • Item 3: Weight = 3, Value = 120
i \ w 0 1 2 3 4 5
0 (No items) 000000
1 (w=1, v=60) 0 60 60 60 60 60
2 (w=2, v=100) 0 60 100 160 160 160
3 (w=3, v=120) 0 60 100 160 180 220

Trace for Cell V[3, 5]: Using item 3 (weight 3, val 120) with capacity 5.
Leave it: V[2, 5] = 160.
Take it: V[2, 5-3] + 120 = V[2, 2] + 120 = 100 + 120 = 220.
Max(160, 220) = 220. So the optimal solution gives a value of 220.

Algorithm Complexity

O(n × W)
Time Complexity: We fill a table of size `n` (number of items) by `W` (maximum weight). Each cell takes O(1). Thus, O(n * W).
Space Complexity: O(n * W) to store the DP matrix.
Roman Urdu: Table mein rows ki tadad items `n` ke barabar hai, aur columns capacity `W` ke barabar. Har khana (cell) fill karne mein constant time lagta hai. Isliye total time `n * W` hai. Isey "Pseudo-polynomial" time bhi kehte hain, kyunke `W` ek number ki value hai, size nahi.

⚡ Lecture 23 - Quick Revision

  • 0/1 Knapsack DP State: V[i, w] = max value using first `i` items with max weight `w`.
  • Formula: max(leave_it, take_it). Taking the item means adding its value and subtracting its weight from remaining capacity.
  • Complexity: O(n * W). It is pseudo-polynomial because the runtime depends on the numeric value of W, not the number of digits in W.
  • What must be remembered: Always check if w_i > w. If the item itself is heavier than the current bag capacity, you CANNOT take it (only the "leave it" option applies).
