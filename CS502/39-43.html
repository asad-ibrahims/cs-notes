Lecture 39: NP-Completeness Reductions (3-SAT to Clique)

What is the Clique Problem?

Technical Definition: A clique in an undirected graph $G = (V, E)$ is a subset of vertices $V' \subseteq V$ such that every pair of vertices in $V'$ is connected by an edge. In other words, $V'$ forms a complete subgraph. The Clique Problem asks: Does $G$ contain a clique of size $k$?
Roman Urdu: Clique ka matlab hai doston ka ek aisa group jahan har koi doosre ko janta ho. Graph theory mein, ye un nodes ka set hai jahan har node baqi tamam nodes ke sath edge se jura ho. Problem ye hai ke kya graph mein $k$ size ka koi aisa group mojood hai? Yeh ek NP-Complete problem hai.

Proving Clique is NP-Complete

To prove a problem is NP-Complete, we must reduce a known NP-Complete problem into it. Here, we reduce 3-CNF SAT to the Clique problem.

$$3\text{-SAT} \le_P \text{Clique}$$

The Reduction Process (How it works)

Given a 3-SAT formula $\Phi$ with $k$ clauses, we construct a graph $G$ such that $G$ has a clique of size $k$ if and only if $\Phi$ is satisfiable.

1
Create Vertices: For each clause (e.g., $C_r = l_1 \lor l_2 \lor l_3$), we create 3 vertices in our graph $G$. Since there are $k$ clauses, we get $3k$ vertices grouped into $k$ clusters.
2
Add Edges: We draw an edge between vertex $v_i$ (from cluster $C_i$) and vertex $v_j$ (from cluster $C_j$) IF:
  • They are in different clusters ($i \neq j$).
  • They are consistent (i.e., we don't connect a literal $x$ to its negation $\bar{x}$).
3
The Logic: If the formula is satisfiable, each clause must have at least one TRUE literal. Selecting that one TRUE vertex from each of the $k$ clusters gives us $k$ vertices. Because they are all consistent (none are negations of each other), there will be edges between all of them, forming a clique of size $k$.
Roman Urdu: Hum formula ki har clause ke liye 3 nodes banate hain. Hum un nodes ko aapas mein jorte (edge lagate) hain jo ek doosre ke dushman na hon (jese $x$ aur $\bar{x}$ ek sath TRUE nahi ho sakte, isliye inme edge nahi lagti). Agar formula TRUE ho sakta hai, toh har clause se ek TRUE literal uthane par ek $k$ size ka clique ban jayega! Is tarah humne prove kiya ke agar Clique solve ho jaye, toh 3-SAT bhi solve ho sakta hai.

⚡ Lecture 39 - Quick Revision

  • Clique: A fully connected subset of vertices in a graph.
  • Reduction Goal: Prove Clique is NP-Complete by translating 3-SAT into it.
  • Graph Construction: Nodes = literals. Edges = consistent literals in different clauses.
  • Result: Formula is satisfiable $\iff$ Graph has a clique of size $k$.

Lecture 40: Vertex Cover Problem

What is the Vertex Cover Problem?

Technical Definition: A Vertex Cover of an undirected graph $G = (V, E)$ is a subset of vertices $V' \subseteq V$ such that every edge $(u, v) \in E$ is incident to at least one vertex in $V'$ (i.e., either $u \in V'$ or $v \in V'$ or both). The problem asks: Is there a vertex cover of size at most $k$?
Roman Urdu: Vertex Cover un nodes ka set hai jo graph ki HAR edge (line) ko touch karte hain. Farz karein edges galiyan (streets) hain aur nodes unke end-points hain. Aapko kam se kam guards (nodes) kharay karne hain taake har gali pe nazar rakhi ja sake.

Proving Vertex Cover is NP-Complete

We prove this by reducing the Clique problem to the Vertex Cover problem.

$$\text{Clique} \le_P \text{Vertex Cover}$$

The Complement Graph ($\bar{G}$)

Given a graph $G=(V, E)$, its complement $\bar{G} = (V, \bar{E})$ has the exact same vertices, but it has edges exactly where $G$ does NOT have edges.

$$\bar{E} = \{ (u,v) \mid u \neq v \text{ and } (u,v) \notin E \}$$

The Reduction Theorem

A graph $G$ has a clique of size $k$ if and only if its complement graph $\bar{G}$ has a vertex cover of size $|V| - k$.

Roman Urdu: Agar $G$ mein $k$ dost hain jo sab ek doosre se jurey hain (Clique), toh uske "Ulte Graph" ($\bar{G}$) mein un doston ke darmiyan koi edge nahi hogi. Iska matlab hai $\bar{G}$ ki sari edges baqi bache hue $|V| - k$ nodes se nikal rahi hongi. Is liye wo baqi nodes ek perfect "Vertex Cover" ban jayenge. Is simple math se prove ho gaya ke Vertex Cover bhi NP-Complete hai.

⚡ Lecture 40 - Quick Revision

  • Vertex Cover: A set of nodes touching every edge in the graph.
  • Reduction Used: $\text{Clique} \le_P \text{Vertex Cover}$.
  • Core Logic: Size of Clique in $G$ is $k \iff$ Size of Vertex Cover in $\bar{G}$ is $|V| - k$.
  • Status: Vertex Cover is NP-Complete.

Lecture 41: Coping with NP-Completeness

The Reality of NP-Completeness

When a problem is proven to be NP-Complete, it means it is highly unlikely that a polynomial-time algorithm (like $O(n^2)$ or $O(n^3)$) exists to find the exact optimal solution. However, in real-world engineering, we still need to solve these problems (like delivery routing, scheduling, etc.).

Roman Urdu: Jab pata chal jaye ke problem NP-Complete hai, toh iska matlab hai "Computer ke bas ki baat nahi" (agar data bada ho). Lekin real life mein companiyon ko apne kaam chalane hote hain. Isliye hum thori compromise (samjhota) karte hain.

Three Main Strategies to Cope

1
Use Small Inputs (Brute Force / Branch-and-Bound):
If the input size $n$ is very small, exponential algorithms $O(2^n)$ or $O(n!)$ might still finish in a few seconds. We can use smart exhaustive search techniques like Branch-and-Bound which prune bad paths early.
2
Heuristics (No Guarantees):
Algorithms like Genetic Algorithms, Simulated Annealing, or A* Search. They try to find a "good" solution quickly. They often work well in practice, but they provide zero mathematical guarantee on how close the answer is to the true optimal.
3
Approximation Algorithms (Guaranteed Bounds):
This is the most scientifically rigorous approach. We design a polynomial-time algorithm that gives a sub-optimal solution, but we mathematically PROVE that the solution is within a certain factor (ratio) of the true optimal.

Approximation Ratio ($\rho(n)$)

An algorithm has an approximation ratio of $\rho(n)$ if, for any input of size $n$, the cost $C$ of the solution produced is bounded by the optimal cost $C^*$ as follows:
$$\max \left( \frac{C}{C^*}, \frac{C^*}{C} \right) \le \rho(n)$$
Roman Urdu: Approximation Ratio ka maqsad ye batana hai ke aapka formula zyada se zyada kitni ghalti karega. Agar $\rho(n) = 2$ hai, iska matlab hai algorithm jo jawab dega wo asal perfect jawab se kabhi bhi double se zyada bura nahi hoga.

⚡ Lecture 41 - Quick Revision

  • Problem: NP-Complete problems take $O(2^n)$ time for exact optimal solutions.
  • Heuristics: Fast, but no guarantees on accuracy.
  • Approximation Algorithms: Fast (Polynomial Time) AND provides a mathematical upper-bound on the error.
  • Approximation Ratio $\rho(n)$: The worst-case ratio between the algorithm's output and the true optimal answer.

Lecture 42: Vertex Cover Approximation Algorithm

The Objective

Since finding the minimum Vertex Cover is NP-Complete, we want a polynomial-time algorithm that finds a vertex cover that is not too much larger than the absolute minimum.

The Approximation Algorithm (Greedy Approach)

Approx-Vertex-Cover(G) C = ∅ // The vertex cover set E' = E[G] // Make a copy of all edges while E' is not empty: Let (u, v) be an arbitrary edge of E' C = C ∪ {u, v} // Add BOTH endpoints to the cover // Remove every edge from E' that touches either u or v Remove from E' every edge incident on u or v return C // Return the cover
Roman Urdu: Algorithm bohat simple hai. Graph ki kisi bhi ek edge ko pakro. Us edge ke dono kono (nodes) ko apne answer (Cover) mein daal lo. Ab kyunke ye dono nodes cover ho gaye hain, in se juri hui jitni bhi aur edges thin, un sab ko list se delete kar do. Ye kaam tab tak karo jab tak sari edges khatam na ho jayen.

Proving the Approximation Ratio is 2

Let $C^*$ be the true optimal minimum vertex cover, and let $C$ be the cover returned by our algorithm. We want to prove that $|C| \le 2 |C^*|$.

  • Let $A$ be the set of edges that our algorithm specifically picked in the while loop.
  • By our algorithm's design, no two edges in $A$ share a common vertex (because as soon as we picked an edge, we deleted all other edges touching its vertices).
  • Therefore, to cover the edges in $A$, ANY valid vertex cover (including the optimal one $C^*$) MUST contain at least one endpoint from every edge in $A$. So, $|C^*| \ge |A|$.
  • Our algorithm greedily adds both endpoints of every edge in $A$. So the size of our cover is exactly $|C| = 2 |A|$.
  • Combining these equations: $|C| = 2 |A| \le 2 |C^*|$.
$$|C| \le 2 \cdot |C^*|$$
Roman Urdu: Kyunke optimal solution $C^*$ ko bhi in edges ko cover karne ke liye har edge se kam az kam 1 node uthana tha, aur humne jaldi mein (greedily) 2 nodes utha liye, toh hamara answer worst-case mein optimal se sirf double (2 times) bada hoga. Isay 2-Approximation Algorithm kehte hain.

Algorithm Complexity

O(V + E)
Time Complexity: Implementing this with Adjacency Lists allows us to traverse each edge and vertex a constant number of times. It runs in linear time $O(V + E)$.

⚡ Lecture 42 - Quick Revision

  • Algorithm: Pick an edge, add BOTH endpoints to cover, delete incident edges. Repeat.
  • Complexity: Extremely fast, $O(V + E)$.
  • Approximation Factor: $\rho(n) = 2$. It is guaranteed to be at most twice the size of the optimal minimum cover.
  • Key Logic: The edges picked are disjoint. Optimal MUST pick at least 1 node per disjoint edge; we picked 2. Thus, $2 \times$ ratio.

Lecture 43: TSP Approximation Algorithm

The Traveling Salesperson Problem (TSP)

Technical Definition: Given a complete graph with weighted edges, find a Hamiltonian Cycle (a tour that visits every vertex exactly once and returns to the start) with the minimum total weight.

TSP is NP-Complete. To approximate it, we must assume the Triangle Inequality holds for the edge weights. This means taking a direct route is always faster or equal to taking a detour.

$$c(u, w) \le c(u, v) + c(v, w) \quad \text{for all } u,v,w \in V$$
Roman Urdu: TSP ka matlab hai ek salesman ko tamam shehron ka chakar laga kar wapis aana hai, sab se kam petrol kharch kar ke. Triangle inequality ka matlab hai ke Shehar A se Shehar C direct jana, hamesha A se B aur phir B se C jane ke muqable mein sasta (ya barabar) hoga.

The Approximation Algorithm (Using MST)

Approx-TSP-Tour(G, c) 1. Select a root vertex r ∈ V[G] 2. Compute a Minimum Spanning Tree (MST) T for G from root r (using Prim's Algorithm) 3. Let L be the list of vertices visited in a Preorder tree walk of T 4. return the Hamiltonian cycle H that visits the vertices in the order L
1
Find MST: A Minimum Spanning Tree connects all cities with the absolute minimum cost, but it has branches (it's not a single circle/tour). Cost of MST $c(T) \le c(H^*)$ (where $H^*$ is optimal TSP tour).
2
Full Walk (DFS): If you walk down every branch of the MST and walk back up, you visit every edge twice. Total cost $= 2 \cdot c(T)$.
3
Preorder & Shortcuts: Instead of walking back through already visited nodes, we skip them and go directly to the next unvisited node (Preorder traversal). Because of the Triangle Inequality, this shortcut is guaranteed to be shorter than walking back!

Proving the Approximation Ratio is 2

Let $H^*$ be the optimal TSP tour. Let $T$ be the MST.

1. If we remove one edge from $H^*$, it becomes a spanning tree. Since $T$ is the minimum spanning tree, its weight must be less than or equal to this broken tour. Thus: $c(T) \le c(H^*)$.

2. A full walk (visiting every edge of $T$ twice) has a cost $W = 2 \cdot c(T)$.

3. Our algorithm's tour $H$ shortcuts the full walk. By triangle inequality, shortcuts don't increase cost. Thus $c(H) \le W$.

4. Putting it together:

$$c(H) \le W = 2 \cdot c(T) \le 2 \cdot c(H^*)$$
$$c(H) \le 2 \cdot c(H^*)$$
Roman Urdu: Kyunke hamara MST optimal tour se sasta tha, aur humne MST ke raston par double chalne (Full walk) ka plan banaya jo optimal se $2\times$ ho gaya. Phir humne shortcut maray jinse karcha aur kam hua. Isliye guarantee hai ke hamara final tour optimal tour ke $2\times$ karchay se hamesha kam ya barabar hoga.

⚡ Lecture 43 - Quick Revision

  • Constraint: This approximation only works if weights follow the Triangle Inequality.
  • Algorithm: 1) Find MST. 2) Do a Preorder Walk (DFS). 3) Connect nodes in that order.
  • Approximation Factor: $\rho(n) = 2$.
  • Key Logic: Cost of MST is less than optimal tour. Walking MST twice is $2 \times$ optimal. Shortcuts only reduce this cost.
