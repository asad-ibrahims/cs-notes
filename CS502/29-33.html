Lecture 29: DAGs & Topological Sort

Directed Acyclic Graphs (DAGs)

Technical Definition: A Directed Acyclic Graph (DAG) is a directed graph with no directed cycles. That means if you start at vertex v and follow the directed edges, you can never return to v.
Roman Urdu: DAG ek aisa graph hai jismein arrows (directions) hoti hain, lekin koi cycle nahi hoti. Yaani aap jahan se chalna shuru karein, ghoom kar wapis ussi jagah nahi aa sakte. Yeh aksar "Dependencies" show karne ke liye use hota hai (jaise CS502 parhne ke liye pehle CS201 aur CS301 pass karna zaroori hai).

What is Topological Sort?

A topological sort of a DAG is a linear ordering of its vertices such that for every directed edge uv (from vertex u to vertex v), u comes before v in the ordering.

Roman Urdu: Asan lafzon mein: Agar kaam B karne se pehle kaam A karna zaroori hai (A → B), toh Topological sort unhe is tarteeb mein rakhega ke A hamesha B se pehle aaye.

The Algorithm using DFS

Topological-Sort(G) 1. Call DFS(G) to compute finish times f[v] for each vertex v 2. As each vertex is finished (color turns BLACK), insert it onto the front of a linked list. 3. return the linked list of vertices.

Idea: A vertex that finishes later in DFS should appear earlier in the topological sort. We sort vertices in descending order of their finish times.

Algorithm Complexity

Θ(V + E)
Time Complexity: We just run standard DFS, which takes $\Theta(V + E)$. Inserting an element at the front of a linked list takes $\Theta(1)$ per vertex. So the total time is completely bounded by the DFS traversal time.

⚡ Lecture 29 - Quick Revision

  • DAG: Directed graph with NO cycles.
  • Topological Sort: Ordering of vertices respecting dependencies. Only possible on DAGs.
  • Trick: Run DFS. Sort nodes by their finish times f[v] in descending order.
  • Complexity: Same as DFS: $\Theta(V + E)$.

Lecture 30: Strongly Connected Components (SCC)

What is a Strongly Connected Component?

Technical Definition: In a directed graph, a Strongly Connected Component (SCC) is a maximal set of vertices such that for every pair of vertices u and v in the set, there is a directed path from u to v AND a directed path from v to u.
Roman Urdu: Ek SCC un nodes ka group hai jahan har node baqi tamam nodes tak (arrows ke zariye) pohanch sakta hai, aur wahan se wapis bhi aa sakta hai. Ek baray graph mein chotay chotay "strongly connected" islands (groups) ho sakte hain.

The Graph Transpose ($G^T$)

The transpose of a graph $G = (V, E)$ is $G^T = (V, E^T)$, where $E^T = \{(v, u) \in V \times V : (u, v) \in E\}$.

Roman Urdu: Graph transpose ka simple matlab hai: Graph mein jitne bhi arrows hain, unki direction ulti (reverse) kar do. A to B tha, toh B to A kar do. Important baat: G aur $G^T$ ke SCCs bilkul same hote hain.

Algorithm to Find SCCs (Kosaraju's Algorithm)

Strongly-Connected-Components(G) 1. Call DFS(G) to compute finish times f[u] for each vertex. 2. Compute GT (transpose the graph). 3. Call DFS(GT), but in the main loop of DFS, visit the vertices in order of decreasing f[u] (from step 1). 4. Output the vertices of each tree in the depth-first forest from step 3 as a separate SCC.

Algorithm Complexity

Θ(V + E)
Time Complexity:
Step 1 (DFS) takes $\Theta(V + E)$.
Step 2 (Transpose) takes $\Theta(V + E)$ if using Adjacency Lists.
Step 3 (DFS on $G^T$) takes $\Theta(V + E)$.
Total time is linear: $\Theta(V + E)$.

⚡ Lecture 30 - Quick Revision

  • SCC: A cluster of nodes where everyone can reach everyone else.
  • Graph Transpose ($G^T$): Reversing all the edges of a graph.
  • Algorithm: 2 passes of DFS. 1st on original graph, 2nd on Transposed graph (in decreasing order of finish times).
  • Complexity: $\Theta(V+E)$. Very efficient!

Lecture 31: Single-Source Shortest Path (Intro)

The Problem

Given a weighted directed graph $G=(V, E)$ and a source vertex $s$, we want to find the shortest (minimum total weight) path from $s$ to every other vertex $v \in V$.

Roman Urdu: Asal zindagi mein jese Google Maps kaam karta hai. Aapka current location "Source" node hai, aur aapko shehar ke har dusre ilaqay tak jane ka sab se chota / sasta raasta nikalna hai. Edges par jo "Weight" hota hai wo distance, time, ya toll-tax kuch bhi ho sakta hai.

Negative Weights and Cycles

  • If a graph has negative weight edges, some shortest path algorithms (like Dijkstra) will fail.
  • If a graph has a Negative Weight Cycle (a loop where the sum of weights is negative), the shortest path is mathematically undefined (because you can keep looping forever to get a path weight of $-\infty$).

Edge Relaxation (Crucial Concept)

Technical Definition: The process of relaxing an edge $(u, v)$ consists of testing whether we can improve the shortest path to $v$ found so far by going through $u$.
Relax(u, v, w) if d[v] > d[u] + w(u, v): d[v] = d[u] + w(u, v) // Update shortest distance π[v] = u // Update parent to u
Roman Urdu: "Relax" karne ka matlab simple yeh hai: Agar `v` tak pohanchne ka current raasta (d[v]) lamba hai, aur `u` ke zariye `v` tak jane ka raasta (d[u] + w) chota hai, toh purane raaste ko bhool jao aur naye chote raaste ko save kar lo.

⚡ Lecture 31 - Quick Revision

  • Problem: Find shortest distance from one start node to all others.
  • Negative Cycles: Make shortest path impossible (keeps decreasing).
  • Relaxation: Updating the distance estimate if a shorter path is found. d[v] = min(d[v], d[u] + w(u,v)).
  • Base Init: Start by setting d[s]=0 and all other d[v]=∞.

Lecture 32: Dijkstra's Algorithm

What is Dijkstra's Algorithm?

Dijkstra's algorithm solves the single-source shortest-paths problem on a weighted, directed graph when all edge weights are non-negative. It is a Greedy Algorithm.

Roman Urdu: Yeh algorithm greedy hai. Yeh hamesha us node ko select karta hai jo abhi tak ke hisaab se sab se qareeb (minimum distance) hai. Phir wahan kharay ho kar apne tamam padosiyon ko dekhta hai aur unke raaston ko "Relax" karta hai. Chuke weights negative nahi hote, isliye ek dafa node "final" ho jaye toh usay dobara check karne ki zaroorat nahi parti.

The Algorithm

Dijkstra(G, w, s) Initialize-Single-Source(G, s) // d[s]=0, all other d[v]=∞ S = ∅ // S contains vertices with final shortest paths Q = V[G] // Q is a Min-Priority Queue keyed by d-values while Q is not empty: u = Extract-Min(Q) // Get node with smallest distance S = S ∪ {u} // Add it to final set for each vertex v in Adj[u]: // For all neighbors of u Relax(u, v, w) // Relax the edge (u, v) // If relaxed, decrease-key operation implicitly happens in Q

Algorithm Complexity

The time complexity heavily depends on how the Min-Priority Queue Q is implemented.

  • Simple Array: Extract-Min takes $O(V)$, done $V$ times = $O(V^2)$. Relax updates take $O(1)$ per edge, total $O(E)$. Overall: $O(V^2 + E) = O(V^2)$. (Good for dense graphs).
  • Binary Min-Heap: Extract-Min takes $O(\log V)$, done $V$ times. Relax (Decrease-Key) takes $O(\log V)$, done $E$ times. Overall: $O((V + E) \log V)$. (Standard implementation, good for sparse graphs).
  • Fibonacci Heap: Decrease-Key takes amortized $O(1)$. Overall: $O(V \log V + E)$. (Fastest theoretically).

⚡ Lecture 32 - Quick Revision

  • Dijkstra's Algorithm: Greedy approach for shortest paths.
  • Constraint: Fails if there are negative weight edges.
  • Key Step: Extract the minimum distance node, lock it in set $S$, and Relax all its outgoing edges.
  • Complexity: Usually $O((V+E)\log V)$ using a binary min-heap.

Lecture 33: Minimum Spanning Trees (Kruskal's Algorithm)

What is a Minimum Spanning Tree (MST)?

Given a connected, undirected, and weighted graph $G$, a Spanning Tree is a subgraph that connects all vertices together without any cycles. A Minimum Spanning Tree (MST) is a spanning tree where the total sum of edge weights is minimized.

Roman Urdu: Farz karein aapne ek naye shehar ke tamam gharon ko bijli ki taron (wires) se jorna hai. Wires lagane ka karcha (cost/weight) har ghar ke darmiyan mukhtalif hai. Aap chahte hain ke aisi tarkeeb se taar bichaayein ke tamam ghar connect bhi ho jayen aur total karcha sab se kam aaye. Koi cycle nahi banni chahiye kyunke cycle mein faltu taar zaya hoti hai. Isay MST kehte hain.

Kruskal's Algorithm (Greedy Approach)

Kruskal's algorithm builds the MST by selecting edges in increasing order of their weights, as long as adding an edge does not form a cycle.

Disjoint-Set Data Structure (Union-Find)

To quickly check if adding an edge forms a cycle, we use a Disjoint-Set structure.

  • Find-Set(u): Returns the representative (parent) of the set containing u. If Find-Set(u) == Find-Set(v), they are already connected. Adding an edge between them would create a cycle!
  • Union(u, v): Merges the two sets containing u and v into one.

The Algorithm

MST-Kruskal(G, w) A = ∅ // A will hold the MST edges for each vertex v in V[G]: Make-Set(v) // Put each vertex in its own set Sort edges of E in non-decreasing order by weight w for each edge (u, v) in the sorted list: if Find-Set(u) ≠ Find-Set(v): // If they are in different trees (NO CYCLE) A = A ∪ {(u, v)} // Add edge to MST Union(u, v) // Merge the two trees return A

Algorithm Complexity

O(E log E) or O(E log V)
Time Complexity: Sorting the edges takes $O(E \log E)$. The disjoint-set operations (Find-Set and Union) take $O(E \alpha(V))$ where $\alpha$ is the very slowly growing inverse Ackermann function. Thus, the time is dominated by the sorting step: $O(E \log E)$. Since $E \le V^2$, $O(\log E) = O(\log V^2) = O(2 \log V) = O(\log V)$. Thus we can also write it as $O(E \log V)$.

⚡ Lecture 33 - Quick Revision

  • MST: Connect all vertices, minimum total cost, NO cycles.
  • Kruskal's Algorithm: Greedy. Sort edges, pick smallest valid edge.
  • Cycle Detection: Handled efficiently using Disjoint Sets (Union-Find).
  • Union-Find Rule: If Find(u) == Find(v), picking edge (u,v) will cause a cycle.
  • Complexity: $O(E \log V)$, mostly due to the edge sorting step.
