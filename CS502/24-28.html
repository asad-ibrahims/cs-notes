Lecture 24: Greedy Algorithms & Activity Selection

What is a Greedy Algorithm?

Technical Definition: A Greedy Algorithm is a paradigm that builds up a solution piece by piece, always choosing the next piece that offers the most immediate (local) benefit. It never reconsiders its choices.
Roman Urdu: Greedy approach ka matlab hai "lalach". Yeh algorithm future ka nahi sochta. Har step par jo choice usay sab se behtar nazar aati hai (local optimum), wo usay select kar leta hai. Is umeed par ke inhi choti best choices se final answer bhi best aayega (global optimum). Yeh DP (Dynamic Programming) se fast hota hai lekin har problem mein optimal solution nahi deta.

Problem: The Activity Selection Problem

Problem Statement: You have a single resource (e.g., a lecture hall) and a set of n activities. Each activity has a start time (s_i) and a finish time (f_i). The goal is to select the maximum number of non-overlapping activities.

The Greedy Idea

Sort the activities by their finish times. Always pick the activity that finishes earliest and doesn't overlap with the previously selected activity. Why? Because finishing early leaves the resource available for the maximum number of future activities.

Greedy-Activity-Selector(s, f) n = length[s] Sort activities by finish times (f_1 ≤ f_2 ≤ ... ≤ f_n) A = {a_1} // Select the first activity j = 1 // j keeps track of the last selected activity for i = 2 to n: if s[i] ≥ f[j]: // If current activity starts AFTER the last one finished A = A U {a_i} // Add to selection j = i // Update last selected return A

Step-by-Step Example

Suppose activities are already sorted by finish time:

Activity (i) 1 2 3 4 5
Start (s) 1 3 0 5 8
Finish (f) 4 5 6 7 9
1
i=1: Select Activity 1 (Finishes at 4). Selection = {1}. Resource is busy until time 4.
2
i=2: Starts at 3. Overlaps (3 < 4). Reject.
3
i=3: Starts at 0. Overlaps (0 < 4). Reject.
4
i=4: Starts at 5. Valid (5 > 4). Select Activity 4. Selection = {1, 4}. Resource busy until time 7.
5
i=5: Starts at 8. Valid (8 > 7). Select Activity 5. Selection = {1, 4, 5}.

Algorithm Complexity

O(n log n)
Time Complexity: Sorting the activities takes `O(n log n)`. The single pass through the activities takes `O(n)`. Total time is dominated by sorting, so `O(n log n)`.
Roman Urdu: Agar activities pehle se time ke hisaab se sorted (tarteeb mein) hoon, toh time sirf `O(n)` lagta hai kyunke humein bas ek dafa loop chalana parta hai. Lekin aam taur par pehle sort karna parta hai, isliye `O(n log n)`.

⚡ Lecture 24 - Quick Revision

  • Core Concept: Greedy makes the locally optimal choice.
  • Activity Selection: Maximize non-overlapping tasks.
  • Greedy Strategy: ALWAYS pick the task that finishes earliest.
  • Complexity: O(n log n) due to sorting.
  • Important: Picking by earliest start time or shortest duration does NOT always give the optimal result. Finish time is the proven optimal greedy choice.

Lecture 25: Huffman Encoding (Greedy)

What is it?

Technical Definition: Huffman coding is a lossless data compression algorithm. It assigns variable-length binary codes to characters based on their frequencies. Most frequent characters get the shortest codes, and least frequent get the longest codes.

It generates Prefix-free codes: No code is a prefix of another code. This ensures there is no ambiguity when decoding the binary string back to characters.

Roman Urdu: Normal ASCII mein har character 8 bits leta hai, chahay wo 'a' ho jo bar bar aata hai, ya 'z' jo bohat kam aata hai. Huffman Encoding ek clever (Greedy) tareeqa hai jismein jo letter zyada use hota hai usay chota code (jaise 2 bits) milta hai, aur jo kam use hota hai usay lamba code milta hai. Is se poori file ka size chota (compress) ho jata hai.

The Huffman Algorithm

Huffman(C) n = |C| Q = build_min_priority_queue(C) // Ordered by frequency for i = 1 to n - 1: allocate a new node z z.left = x = Extract-Min(Q) // Get lowest frequency node z.right = y = Extract-Min(Q) // Get second lowest frequency node z.freq = x.freq + y.freq // Combine frequencies Insert(Q, z) // Put the combined node back in queue return Extract-Min(Q) // Return the root of the tree

Step-by-Step Example

Given characters and their frequencies: A: 5, B: 9, C: 12, D: 13, E: 16, F: 45.

1
Initial Min-Queue: [A:5, B:9, C:12, D:13, E:16, F:45]
2
Take two minimums: A(5) and B(9). Merge into node AB(14).
Queue becomes: [C:12, D:13, AB:14, E:16, F:45]
3
Take two minimums: C(12) and D(13). Merge into node CD(25).
Queue becomes: [AB:14, E:16, CD:25, F:45]
4
Take minimums: AB(14) and E(16). Merge into ABE(30).
Queue becomes: [CD:25, ABE:30, F:45]
5
Continue this process until 1 node is left (the root of the Huffman Tree). Going Left gives bit `0`, going Right gives bit `1`.

Algorithm Complexity

O(n log n)
Time Complexity: Building the initial priority queue takes `O(n)`. The loop runs `n-1` times, and each `Extract-Min` and `Insert` operation in a min-heap takes `O(log n)`. Total time is `O(n log n)`.
Roman Urdu: Humne characters ko frequencies ke hisaab se sort rakhne ke liye ek Priority Queue (Min-Heap) use kiya hai. Heap mein se min nikalne aur naya node dalne ka time `log n` hota hai. Ye kaam `n` dafa hota hai, toh total time `n log n`.

⚡ Lecture 25 - Quick Revision

  • Goal: File Compression (variable-length coding).
  • Algorithm Type: Greedy approach.
  • Prefix-Free: No code is the start of another, avoiding ambiguity.
  • Tree Construction: Always merge the two nodes with the lowest frequencies.
  • Complexity: O(n log n) due to Priority Queue / Heap operations.

Lecture 26: Graph Terminology & Representation

What is a Graph?

Technical Definition: A graph G = (V, E) is a mathematical structure consisting of a set of Vertices V (or nodes) and a set of Edges E that connect pairs of vertices.
  • Directed Graph (Digraph): Edges have a direction (like a one-way street). $(u, v)$ means an edge from u to v.
  • Undirected Graph: Edges have no direction (like a two-way street). $(u, v)$ is the same as $(v, u)$.
  • Weighted Graph: Edges have a weight (cost, distance, etc.) associated with them.
Roman Urdu: Graph asal mein networks ko represent karne ka tareeqa hai. Jese cities (vertices) aur unke darmiyan roads (edges). Agar road one-way hai, toh wo Directed graph hai. Agar aana-jana dono side allowed hain, toh Undirected graph hai.

How is a Graph Represented?

Computers cannot "look" at a picture of a graph. We need to store it in memory. There are two primary ways:

1. Adjacency Matrix

A 2D array A of size |V| × |V|. A[i][j] = 1 if there is an edge from vertex i to vertex j, otherwise A[i][j] = 0.

Space Complexity: O(V2). (A 500-vertex graph needs a 500x500 matrix).
Pros: Checking if an edge exists between u and v is extremely fast O(1).
Cons: Wastes a lot of memory if the graph is sparse (has very few edges), because mostly it will store 0s.

2. Adjacency List (Standard Choice)

An array of size |V| where each index represents a vertex, and contains a linked list of all the vertices it is connected to (its neighbors).

Space Complexity: O(V + E). (It only stores the edges that actually exist).
Pros: Extremely memory efficient for sparse graphs. Finding all neighbors of a vertex is fast.
Cons: Checking if a specific edge (u, v) exists takes O(degree(u)) time (you have to traverse the list).

⚡ Lecture 26 - Quick Revision

  • V: Vertices (Nodes). E: Edges (Links).
  • Adjacency Matrix: 2D Array. Space: `O(V²)`. Best for dense graphs.
  • Adjacency List: Array of linked lists. Space: `O(V + E)`. Best for sparse graphs.
  • Common Mistake: Forgetting that in an undirected graph's Adjacency List, an edge between A and B must appear twice (in A's list and B's list).

Lecture 27: Breadth-First Search (BFS)

What is BFS?

Technical Definition: BFS is a graph traversal algorithm that explores the graph level-by-level, starting from a source vertex. It visits all direct neighbors of the source first, then the neighbors of those neighbors, and so on.
Roman Urdu: BFS pani ki lehar (wave) ki tarah kaam karta hai. Jis node se hum shuru karte hain, pehle uske tamam direct padosiyon (neighbors) ke paas jata hai (Level 1). Phir un padosiyon ke padosiyon ke paas (Level 2). Yeh algorithm shortest path (kam se kam edges wala raasta) find karne ke liye istemal hota hai.

Core Concept: BFS uses a Queue (FIFO) data structure to keep track of nodes to visit.

Colors in Graph Traversal

To keep track of progress and avoid infinite loops, nodes are colored:

  • White: Undiscovered (Not visited yet).
  • Gray: Discovered, but its neighbors are not fully explored yet (Currently in the Queue).
  • Black: Fully explored (Removed from the Queue, all neighbors visited).

The BFS Algorithm

BFS(G, s) // Graph G, Source vertex s for each vertex u in V[G] - {s}: color[u] = WHITE d[u] = infinity // Distance from source π[u] = NIL // Parent node color[s] = GRAY d[s] = 0 π[s] = NIL Q = Empty Queue Enqueue(Q, s) while Q is not empty: u = Dequeue(Q) for each neighbor v of u: if color[v] == WHITE: // Unvisited neighbor found color[v] = GRAY // Mark discovered d[v] = d[u] + 1 // Distance is parent's dist + 1 π[v] = u // Set parent pointer Enqueue(Q, v) color[u] = BLACK // Node u is completely processed

Algorithm Complexity

O(V + E)
Time Complexity: Each vertex is enqueued and dequeued exactly once O(V). The inner loop iterates over the adjacency list of each vertex. The sum of all adjacency list lengths is proportional to the number of edges O(E). Total time = O(V + E).
Roman Urdu: Kyunke hum har node (V) ko Queue mein ek dafa dalte aur nikalte hain, aur graph ke har edge (E) ko ziyada se ziyada 2 dafa check karte hain, isliye total time V aur E ke sum ke barabar hota hai. Agar Adjacency Matrix use karein, toh time O(V²) ho jata.

⚡ Lecture 27 - Quick Revision

  • Data Structure: BFS relies strictly on a Queue.
  • Exploration Style: Level-by-level (Wave-front).
  • Main Application: Finding the Shortest Path in an unweighted graph.
  • Complexity: O(V + E) with Adjacency List.
  • Node Colors: White (New) -> Gray (In Queue) -> Black (Done).

Lecture 28: Depth-First Search (DFS)

What is DFS?

Technical Definition: DFS is a graph traversal algorithm that explores as deeply as possible along each branch before backtracking. It relies heavily on recursion (which implicitly uses a Stack).
Roman Urdu: DFS ek bhool-bhulaiya (maze) mein rasta dhoondne ki tarah hai. Aap ek raste par tab tak chalte rehte hain jab tak dead-end na aa jaye. Jab aage jane ka rasta na mile, toh aap peeche (backtrack) aate hain aur koi aur rasta try karte hain. BFS "wide" jata tha, DFS "deep" jata hai.

Core Concept: DFS uses a Stack (LIFO) mechanism (usually via recursion calls).

Timestamps in DFS

Unlike BFS which uses distances, DFS assigns two important timestamps to every vertex. A global time variable ticks up every time a node is discovered or finished.

  • d[u] (Discovery Time): The time when vertex `u` is first visited (turns GRAY).
  • f[u] (Finish Time): The time when DFS has completely explored all of `u`'s neighbors and backtracks (turns BLACK).

The DFS Algorithm

DFS(G) for each vertex u in V[G]: color[u] = WHITE π[u] = NIL time = 0 for each vertex u in V[G]: if color[u] == WHITE: DFS-Visit(u) DFS-Visit(u) color[u] = GRAY // Mark discovered time = time + 1 d[u] = time // Record discovery time for each neighbor v of u: if color[v] == WHITE: π[v] = u DFS-Visit(v) // Recursively visit neighbor (Go Deep!) color[u] = BLACK // Mark finished time = time + 1 f[u] = time // Record finish time

Algorithm Complexity

O(V + E)
Time Complexity: The initialization takes `O(V)`. DFS-Visit is called exactly once for each vertex (because it only runs on WHITE nodes). The inner loop of DFS-Visit looks at every edge once (in a directed graph) or twice (in undirected). Total time = O(V + E).
Roman Urdu: BFS ki tarah, yahan bhi har node ek dafa visit hota hai, aur har edge check hoti hai. Isliye iska time bhi O(V + E) hi rehta hai (agar Adjacency List use ho).

⚡ Lecture 28 - Quick Revision

  • Data Structure: DFS relies on a Stack (via Recursion).
  • Exploration Style: Go as deep as possible, then backtrack.
  • Timestamps: Every node gets a discovery time `d[u]` and a finish time `f[u]`. These are crucial for advanced algorithms (like Topological Sort or finding Strongly Connected Components).
  • Parenthesis Theorem: For any two nodes `u` and `v`, their `[d, f]` intervals are either entirely disjoint, or one is completely contained within the other.
  • Complexity: O(V + E) with Adjacency List.
