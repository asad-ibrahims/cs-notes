Lecture 34: Prim's Algorithm (Minimum Spanning Tree)

What is Prim's Algorithm?

Technical Definition: Prim's Algorithm is a greedy algorithm that finds a Minimum Spanning Tree (MST) for a weighted undirected graph. Unlike Kruskal's, which builds a forest and merges trees, Prim's starts with a single vertex and continuously grows a single tree by adding the cheapest edge that connects a vertex in the tree to a vertex outside the tree.
Roman Urdu: Kruskal poore graph ki edges ko sort kar ke choti edges uthata tha. Prim's ka style thora alag hai. Yeh kisi ek "Source" node se shuru karta hai. Phir check karta hai ke is node ke padosiyon (neighbors) mein sab se sasti edge konsi hai. Jo sab se sasti hoti hai, usko apne MST mein shamil kar leta hai. Phir connected nodes se mazeed sasti edges dhoondta hai, jab tak tamam nodes connect na ho jayen.

The Algorithm

We use a Min-Priority Queue Q to keep track of vertices outside the tree, keyed by the minimum edge weight connecting them to the tree (key[v]).

MST-Prim(G, w, r) // Graph G, weights w, root node r for each u ∈ V[G]: key[u] = ∞ π[u] = NIL key[r] = 0 // Start at root Q = V[G] // Put all vertices in Min-Priority Queue while Q is not empty: u = Extract-Min(Q) // Get node with minimum connecting cost for each v ∈ Adj[u]: // If v is still in Q and edge (u,v) is cheaper than v's current key if v ∈ Q and w(u, v) < key[v]: π[v] = u // Set u as parent key[v] = w(u, v) // Update minimum cost to reach v (Decrease-Key)

Algorithm Complexity

O(E log V)
Time Complexity: If the Min-Priority Queue is implemented using a Binary Heap, Extract-Min takes $O(\log V)$ and is called $V$ times. The inner Decrease-Key operation takes $O(\log V)$ and can be called up to $E$ times. Total time is $O(V \log V + E \log V) = O(E \log V)$.
Roman Urdu: Iski complexity bilkul Kruskal jitni hi hai ($O(E \log V)$). Agar graph mein edges bohat zyada hain (dense graph) aur hum Fibonacci heap use karein, toh yeh $O(E + V \log V)$ ban sakta hai jo thora aur fast hai.

⚡ Lecture 34 - Quick Revision

  • Algorithm Type: Greedy approach for MST.
  • Strategy: Grow a single tree from a root node.
  • Data Structure: Min-Priority Queue (keyed by edge weight).
  • Comparison: Kruskal sorts edges first. Prim maintains a priority queue of vertices.
  • Complexity: $O(E \log V)$ using a binary min-heap.

Lecture 35: Bellman-Ford Algorithm

The Problem with Dijkstra

Dijkstra's algorithm is fast but it fails if the graph has negative weight edges. Once Dijkstra extracts a node from the Priority Queue, it assumes its shortest path is final. Negative edges can provide a "shortcut" later that Dijkstra misses.

Roman Urdu: Dijkstra ko lagta hai ke agar rasta aage ja raha hai toh distance barhega (kyunke negative distance allowed nahi). Lekin agar koi negative edge (-5) aa jaye, toh purana mehnga rasta achanak sasta ho sakta hai. Is maslay ko hal karne ke liye hum Bellman-Ford use karte hain.

The Bellman-Ford Idea

Technical Concept: Instead of being greedy, Bellman-Ford takes a "safe" approach. It simply relaxes ALL edges in the graph, over and over again, exactly $|V| - 1$ times.

Why $|V| - 1$ times? Because the longest possible simple path (no cycles) in a graph with $|V|$ vertices can have at most $|V| - 1$ edges. By relaxing all edges $|V| - 1$ times, we guarantee that the shortest path information has propagated to all nodes.

The Algorithm & Cycle Detection

Bellman-Ford(G, w, s) Initialize-Single-Source(G, s) // 1. Relax all edges |V| - 1 times for i = 1 to |V| - 1: for each edge (u, v) ∈ E[G]: Relax(u, v, w) // 2. Check for Negative-Weight Cycles for each edge (u, v) ∈ E[G]: if d[v] > d[u] + w(u, v): return FALSE // Negative cycle detected! Shortest path undefined. return TRUE // Success
Roman Urdu: Agar V-1 passes lagane ke baad bhi koi edge "Relax" ho rahi hai (yani distance mazeed chota ho raha hai), iska saaf matlab hai ke graph mein ek Negative Cycle (ghoomti hui negative loop) majood hai. Aisi surat mein algorithm FALSE return karta hai, kyunke minimum distance $-\infty$ ho jayega.

Algorithm Complexity

O(V × E)
Time Complexity: The initialization takes $O(V)$. The main loops run $V-1$ times, and in each iteration, we iterate over all $E$ edges. The final check loop takes $O(E)$. Overall time is strictly $O(V \times E)$.
Space Complexity: $O(V)$ to store distances and parents.
Roman Urdu: Dijkstra ($O(E \log V)$) se kaafi slow hai, isliye isay sirf tab use karte hain jab graph mein negative weights ka khatra ho.

⚡ Lecture 35 - Quick Revision

  • Purpose: Single-source shortest path WITH negative weights.
  • Core Mechanism: Relax ALL edges exactly $V-1$ times.
  • Bonus Feature: Can detect Negative Weight Cycles (returns FALSE).
  • Complexity: $O(V \cdot E)$. Safe, but slower than Dijkstra.

Lecture 36: Floyd-Warshall Algorithm (All-Pairs)

All-Pairs Shortest Path Problem

Instead of finding paths from a single source, we want to find the shortest path between every pair of vertices $i$ and $j$ in the graph. We could run Dijkstra or Bellman-Ford $V$ times (once for each vertex), but dynamic programming gives us an elegant solution: The Floyd-Warshall Algorithm.

Roman Urdu: Is baar humein har shehar se har dosre shehar ka sab se chota rasta chahiye. Hum ek 2D matrix banate hain. Is matrix ko hum Ahista Ahista update karte hain yeh check kar ke ke "kya kisi teesre shehar (intermediate node) ke zariye jana direct jane se sasta hai?"

Dynamic Programming Concept

Let the vertices be numbered $1, 2, ..., V$.
Let $D^{(k)}_{ij}$ be the weight of the shortest path from $i$ to $j$ using only vertices from $\{1, 2, ..., k\}$ as intermediate vertices.

The Recurrence Formula:

D(k)[i, j] = min( D(k-1)[i, j], D(k-1)[i, k] + D(k-1)[k, j] )
  • Option 1 (Don't use k): The shortest path without node $k$ is $D^{(k-1)}_{ij}$.
  • Option 2 (Use k): Go from $i$ to $k$, then $k$ to $j$. Cost is $D^{(k-1)}_{ik} + D^{(k-1)}_{kj}$.

The Algorithm

Floyd-Warshall(W) // W is the adjacency matrix of weights n = rows[W] D = W // Initialize distance matrix for k = 1 to n: for i = 1 to n: for j = 1 to n: // Relax via vertex k if D[i][k] + D[k][j] < D[i][j]: D[i][j] = D[i][k] + D[k][j] return D

Algorithm Complexity

O(V3)
Time Complexity: The algorithm has three extremely simple nested loops, each iterating $V$ times. Total time is exactly $\Theta(V^3)$.
Space Complexity: $O(V^2)$ to store the 2D distance matrix.
Roman Urdu: 3 loops hain jo $n$ dafa chalti hain. Isliye time complexity hamesha $n^3$ hoti hai. Yeh algorithm chotay graphs (dense graphs) ke liye bohat acha hai kyunke loops ke andar ka code bohat sada aur fast hai (low constant factors).

⚡ Lecture 36 - Quick Revision

  • Goal: Shortest paths between ALL pairs of vertices.
  • Approach: Dynamic Programming. Checks if routing through intermediate vertex k is cheaper.
  • Graph Constraints: Can handle negative edges, but assumes NO negative-weight cycles.
  • Complexity: $O(V^3)$ Time, $O(V^2)$ Space. (Simple 3 nested loops).

Lecture 37: Complexity Theory Intro (P vs NP)

Why Complexity Theory?

So far, we have seen algorithms that run in $O(n^2)$, $O(n \log n)$, or $O(n^3)$ time. These are called Polynomial Time algorithms, and we consider them "efficient" or "tractable". However, there are problems for which no polynomial-time algorithm has ever been found. They seem to require exponential time $O(2^n)$.

Roman Urdu: Kuch problems aise hain jo computer ke liye jaldi solve karna taqreeban namumkin hai, khas tor pe jab data bara (large $n$) ho jaye. Complexity theory humein un mushkil problems ko pehchan'na (classify karna) sikhati hai, taake hum ek aisi problem ko hal karne par waqt zaya na karein jiska koi fast solution majood hi nahi.

Decision Problems vs Optimization Problems

  • Optimization Problem: Find the shortest path from A to B. (Answers are values/structures).
  • Decision Problem: Is there a path from A to B with distance at most $k$? (Answers are just YES or NO).

Complexity Theory focuses almost entirely on Decision Problems because they are mathematically easier to analyze, and if a decision problem is hard, its corresponding optimization problem is at least as hard.

The Classes: P and NP

Class P (Polynomial Time): The set of decision problems that can be solved in polynomial time by a deterministic computer. (e.g., Is a number even? Is there a path from A to B?)
Class NP (Non-Deterministic Polynomial Time): The set of decision problems where if the answer is "YES", there exists a "certificate" (a proof or a solution) that can be verified in polynomial time.

Note: "NP" does NOT stand for "Not Polynomial".

Roman Urdu:
P Class: Computer jaldi khud solve kar sakta hai. (Jaise array ko sort karna).
NP Class: Computer shayad jaldi solve na kar sake, lekin agar aap usay ek "Answer" dein, toh wo jaldi (polynomial time mein) check (verify) zaroor kar lega ke answer theek hai ya nahi. Jaise Sudoku solve karna mushkil hai, lekin solved Sudoku check karna bohat asan hai.
Har problem jo P mein hai, wo NP mein bhi aati hai ($P \subseteq NP$).

⚡ Lecture 37 - Quick Revision

  • Polynomial Time (Tractable): $O(n^c)$. Efficient.
  • Exponential Time (Intractable): $O(c^n)$. Inefficient for large inputs.
  • Decision Problems: Have YES/NO answers. Used for complexity theory.
  • Class P: Problems SOLVABLE in polynomial time.
  • Class NP: Problems VERIFIABLE in polynomial time. (If I give you a solution, you can check it quickly).

Lecture 38: NP-Completeness & Reductions

What is NP-Complete (NPC)?

A problem is NP-Complete if it is in NP, and it is as hard as every other problem in NP.

The Big Implication: If anyone can find a polynomial-time algorithm for even one single NP-Complete problem, then ALL problems in NP can be solved in polynomial time. This would prove that P = NP (The biggest unsolved problem in Computer Science).
Roman Urdu: NP-Complete problems class NP ke "Boss" hain. Agar boss defeat ho gaya (yani kisi NP-Complete ka fast solution mil gaya), toh sab defeat ho jayenge (P=NP ho jayega). Duniya ke hazaron mushkil problems (scheduling, routing) NP-Complete hain.

Polynomial-Time Reduction ($A \le_P B$)

How do we prove a problem $B$ is NP-Complete? We use a technique called Reduction. We show that a known hard problem $A$ can be transformed into problem $B$ in polynomial time.

  • If we can easily convert problem $A$ into problem $B$, then $B$ must be at least as hard as $A$.
  • If $A$ is known to be NP-Complete, and $A$ reduces to $B$, then $B$ is also NP-Complete.
Roman Urdu: Reduction ka matlab hai bhes badalna (translation). Agar main kisi English sentence (Problem A) ko Urdu (Problem B) mein jaldi translate kar sakta hoon, toh iska matlab hai agar main Urdu ko hal kar sakta hoon, toh English bhi hal ho jayegi. Is tarah hum nayi nayi problems ko NP-Complete prove karte hain.

The First NP-Complete Problem: SAT

The Boolean Satisfiability Problem (SAT) asks: Given a boolean logic formula (with AND, OR, NOT variables), is there an assignment of TRUE/FALSE to the variables that makes the whole formula evaluate to TRUE?

Stephen Cook proved in 1971 that SAT is NP-Complete. Every subsequent NP-Complete proof starts by reducing SAT (or 3-SAT) to the new problem.

Coping with NP-Completeness

Since we can't solve NP-Complete problems exactly in fast time, what do we do in real life?

  1. Heuristics: Use rule-of-thumb algorithms that give a "good enough" solution quickly, but without mathematical guarantees of optimality.
  2. Approximation Algorithms: Fast algorithms that guarantee the answer is within a specific percentage (factor) of the true optimal answer.
  3. Brute Force (for small n): If the input size is very small, $O(2^n)$ might still run in milliseconds.

⚡ Lecture 38 - Quick Revision

  • NP-Complete: The hardest problems in NP. If one is in P, then P=NP.
  • Reduction ($A \le_p B$): Transforming inputs of problem A to problem B in polynomial time. Proves B is as hard as A.
  • Cook's Theorem: Proved SAT is the first NP-Complete problem.
  • Handling NPC: If a problem is NPC, don't try to find a perfect fast algorithm. Use Heuristics, Approximation, or try to solve special simplified cases.
